## 使用方法

每项按下面等级自评，不允许只因“看过教程”判定掌握：

| 等级 | 判断标准 |
| :--- | :--- |
| 0 | 没接触或无法解释 |
| 1 | 看资料能跟做 |
| 2 | 不看教程能独立完成，并能解释关键机制 |

## 六、必须能回答的问题

### Linux 与系统编程

1. 用户态和内核态为什么要隔离？系统调用处于什么位置？
2. 进程和线程共享、独享哪些资源？
3. `fork` 后发生了什么？为什么通常紧接 `exec`？
4. mutex、semaphore、condition variable 分别适合什么场景？
5. 为什么一次 `write`/`send` 可能没有处理全部数据？
6. TCP 为什么会出现半包和粘包？你的协议如何处理？
7. 阻塞、非阻塞、同步、异步是否是同一组概念？
8. `select`、`poll`、`epoll` 的主要差别是什么？
9. 程序文件明明存在，为什么执行时可能报 `No such file or directory`？
10. 如何定位一个进程 CPU 高、内存增长、卡住或端口不通的问题？

### 启动、内核与驱动

11. 从上电到业务程序运行经历哪些阶段？每层失败有什么现象？
12. U-Boot、Kernel、DTB、RootFS 分别是什么，谁加载谁？
13. 内核如何知道板上挂了哪些不能自动枚举的设备？
14. `compatible` 如何匹配驱动？节点存在为何仍可能 probe 失败？
15. `insmod` 和 `modprobe` 有什么区别？`Invalid module format` 怎么查？
16. 字符设备为什么需要主次设备号和 `file_operations`？
17. 为什么不能在内核中直接解引用用户指针？
18. 什么上下文不能睡眠？mutex 和 spinlock 如何选择？
19. 中断处理为什么要尽量短？延后工作有哪些方式？
20. 为什么 DMA 不能直接使用普通虚拟地址？

### 工程与项目

21. 交叉编译器、sysroot 和目标板动态库如何保持兼容？
22. Buildroot 的 `host`、`staging`、`target`、`images` 分别是什么？
23. 为什么不能长期手改 `output/target` 或 `output/build`？
24. 你的网关在断网、坏帧、队列满和进程退出时分别如何处理？
25. 项目中最难定位的问题是什么？你用什么证据排除了其他假设？

回答要求：先给结论，再讲机制，最后给自己项目里的证据。不会的明确边界，不用术语堆叠掩盖。

## 七、现场操作验收

在不打开教程的情况下完成：

1. 登录开发板，找出 OS、内核、内存、根分区、IP 和监听服务。
2. 在 WSL 交叉编译程序，判断 ELF 架构，传到板端运行。
3. 主动造成动态库或权限错误，再用工具定位。
4. 调试一个崩溃程序，拿到带源码行号的调用栈。
5. 读取一个真实外设，说明设备树、驱动、设备节点和应用调用链。
6. 加载模块并从 `dmesg`、`lsmod`、`/sys` 验证结果。
7. 停止和重启自己的网关服务，模拟断网后观察恢复。
8. 从干净环境按文档重新构建项目。

## 九、岗位匹配判断

### 可以重点投递

- 嵌入式 Linux 应用开发。
- 物联网网关、设备接入、网络通信开发。
- Linux/ESP32 技术支持与解决方案岗位。
- 要求 0～1 年经验、工作内容包含基础 BSP/外设调试的岗位。

### 可以投，但要诚实说明深度

- 初级 Linux 驱动/BSP：需要有模块、设备树和至少一个真实外设的证据。
- 系统定制/Buildroot：需要能展示 package、启动服务和可复现镜像。

### 暂不把它作为主攻标签

- 要求独立新板 bring-up、复杂内核驱动或长期内核维护的岗位。
- 要求熟练 Yocto、Android BSP、V4L2/DRM/ALSA 等专项经验的岗位。

当前实习中的客户问题处理并非无效经历。把它整理成“问题分层、复现条件、证据、根因、修复和客户验证”，再叠加 Linux 网关项目，会比笼统写“使用 AI 完成开发”更有说服力。
