# 嵌入式 Linux 专区

> 当前主线：以泰山派一类 ARM64 开发板为实验平台，从 Linux 应用开发进入，再理解启动链、设备树、驱动与系统构建。目标不是两个月内“学完内核”，而是建立一条能独立开发、调试和继续深入的完整链路。

## 一、从 MCU 到 Linux，要补什么

已有的 ESP32、STM32、RTOS 和 C 语言经验不会清零，它们会成为理解 Linux 驱动与并发的基础。真正新增的是下面四层：

| 层次 | 需要建立的能力 | 与 MCU 开发的主要区别 |
| :--- | :--- | :--- |
| Linux 使用 | Shell、权限、进程、网络、日志、软件包 | 不再只有一个固件和一个地址空间 |
| 应用开发 | POSIX API、线程、IPC、Socket、交叉编译 | 应用运行在用户态，通过系统调用访问内核 |
| 系统理解 | Bootloader、Kernel、DTB、RootFS | 一个可启动系统由多个独立产物组成 |
| BSP 与驱动 | 设备树、驱动模型、内核模块、外设框架 | 硬件描述与驱动代码分离，受内核框架管理 |

## 二、专区学习顺序

```text
Linux 基础
   ↓
交叉编译、Make/CMake、ELF
   ↓
文件 I/O、进程、线程、IPC、网络
   ↓
BootROM → U-Boot → Kernel + DTB → RootFS
   ↓
设备树、内核模块、驱动模型
   ↓
Buildroot 定制系统 + 综合项目
```

建议严格按顺序推进。驱动并不是第一站：若还不能解释进程、虚拟内存、文件描述符和阻塞 I/O，直接抄字符设备驱动只会记住模板。

## 四、两个月后的合理目标

完成本专区的核心实验后，应达到以下水平：

- 能独立使用串口和 SSH 登录板卡，分析启动日志、进程、端口、存储和资源占用。
- 能为 ARM64 交叉编译 C/C++ 程序，解释 ELF、动态库、sysroot 和“板上运行不了”的常见原因。
- 能编写包含文件 I/O、线程、IPC、Socket 的 Linux 应用，并用 GDB、strace 和日志定位问题。
- 能讲清完整启动链，读懂基础 DTS，修改一个简单设备节点并验证是否生效。
- 能编译、加载和卸载简单内核模块，理解字符设备与 platform driver 的职责。
- 能用 Buildroot 构建或定制一个可复现系统，并完成一个有文档、有日志、有调试记录的项目。

这个阶段适合投递嵌入式 Linux 应用开发、初级 BSP/驱动、Linux 技术支持或物联网网关方向岗位；距离独立完成 SoC 适配、复杂驱动和内核疑难问题定位仍有明显距离。

## 五、学习原则

1. **先运行，再解释**：每个概念都必须有对应命令、代码或上板现象。
2. **先用户态，再内核态**：能用 `libgpiod`、`i2c-dev`、`spidev` 完成的实验，先在用户态走通。
3. **保留证据**：记录串口日志、构建命令、关键报错、修复过程和验证结果。
4. **AI 只做辅助**：自己能解释每个 API、编译参数和错误原因，才算掌握生成的代码。
5. **一次只维护一条主线**：前 8 周暂不同时深挖 Yocto、Android、V4L2、ALSA 和复杂总线驱动。
