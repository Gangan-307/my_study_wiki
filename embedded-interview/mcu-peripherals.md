# MCU 与外设基础题

[返回专区](/embedded-interview/index.md) | [复习与自测表](/embedded-interview/review-plan.md)

学习要求：能把 API 参数对应到原理图、时序和数据手册；遇到外设不工作时，按供电、连接、复用、时钟、配置、协议逐层验证。Cortex-M 的规则不能直接推广到所有 ESP32 型号或其他架构。

## M01：推挽、开漏、上拉分别是什么？ :id=m01

**参考回答：** 推挽输出可以主动驱动高、低电平；开漏输出只能主动拉低，释放后通常依靠上拉获得高电平。上拉/下拉为输入或释放状态提供默认电平。开漏适合多个器件共享线路，例如常见 I2C 总线。

**易错点：** 开漏“写 1”通常表示释放线路，不是主动输出高电平。内部上拉可能太弱，上升时间由上拉电阻与总线电容共同决定。开漏不代表引脚可以承受任意上拉电压，仍要看电气规格。

**面试追问：** 两个推挽输出一个高、一个低接在一起会怎样？I2C 上拉阻值太大或太小各有什么问题？

## M02：UART 参数有哪些？乱码如何定位？ :id=m02

**参考回答：** 双方要匹配波特率、数据位、校验位、停止位和必要的流控。常见 `115200 8N1` 表示 115200 波特、8 数据位、无校验、1 停止位。UART 数据线常按 TX 接对方 RX，并使用相容电平与参考地。

**易错点：** 3.3V UART、RS-232、RS-485 的电气层不同。8N1 每个字节通常占 10 位，因此理想有效字节率约为波特率除以 10，还未计入软件与协议开销。乱码不一定是程序编码问题。

**面试追问：** 先后检查 TX/RX、共地、电平、实际位宽、时钟误差、流控与溢出，分别需要什么证据？

## M03：UART 中断、DMA 和 IDLE 怎样配合接收？ :id=m03

**参考回答：** 中断接收适合低速或小数据，DMA 适合连续搬运较多数据，减少逐字节中断。IDLE 检测线路空闲，可作为“现在有一批数据待处理”的通知。解析任务仍要按协议长度、分隔符和校验确定完整消息。

**易错点：** IDLE 不是通用帧结束标志，一帧内可能有停顿，多帧也可能连续到达。DMA 环形缓冲区需要区分写入位置、已消费位置、回绕和覆盖；停止再启动 DMA 的窗口也可能丢字节。

**面试追问：** 收到半帧、两帧连续数据、缓冲区满时各怎么办？为何 ISR 里不宜做完整 JSON 解析？

## M04：I2C 的 7 位地址、ACK/NACK 与重复起始是什么？ :id=m04

**参考回答：** 常见 I2C 使用 SDA、SCL 两线，START 后发送 7 位器件地址与一位读写方向，接收方在第 9 个时钟给 ACK/NACK。读寄存器常先写寄存器地址，再用重复 START 切换为读。具体序列按器件手册确定。

**易错点：** 器件 7 位地址 `0x3C` 对应总线写地址字节 `0x78`、读地址字节 `0x79`。SDK 有的接受 7 位地址，有的参数要求左移；以 API 文档为准。控制器读取最后一字节后主动 NACK，通常是正常结束，不一定是故障。

**面试追问：** 逻辑分析仪显示的 `0x3C` 与手册里的 `0x78` 为何可能是同一地址？SDA 一直为低时，应如何区分设备挂死与线路问题？

## M05：SPI 四种模式怎么区分？ :id=m05

**参考回答：** CPOL 决定时钟空闲电平，CPHA 决定在第一个还是第二个时钟边沿采样。这里“第一个边沿”指从空闲电平离开的边沿。模式、频率、位序、字长和片选时序都要与从设备一致。

| 模式 | CPOL | CPHA | 空闲电平 | 采样边沿 |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 0 | 0 | 低 | 上升沿 |
| 1 | 0 | 1 | 低 | 下降沿 |
| 2 | 1 | 0 | 高 | 下降沿 |
| 3 | 1 | 1 | 高 | 上升沿 |

**易错点：** SPI 常见实现没有类似 I2C 的地址 ACK，发送 API 成功不代表从设备已正确理解。四线 SPI 可全双工传输，但某个器件协议可能只使用其中一部分；读数据时主机通常也要发送 dummy 数据产生时钟。

**面试追问：** 读回一直为 `0xFF` 或 `0x00`，如何检查片选、MISO 连接、模式和 dummy cycle？

## M06：中断优先级与任务优先级一样吗？ :id=m06

**参考回答：** 硬件中断由处理器中断控制器决定响应和嵌套，任务优先级由 RTOS 调度器决定。Cortex-M NVIC 通常是数字越小越紧急，实际有效位数和优先级分组由芯片及配置决定；不能套用任务优先级的编号规则。

**易错点：** Cortex-M 的抢占优先级决定能否打断正在执行的 ISR，子优先级用于同抢占级待处理中断的选择。高于 RTOS 系统调用阈值的中断，通常不能调用内核 API，即使 API 带 `FromISR` 也要遵守限制。

**面试追问：** 为什么把 UART 中断设到最高紧急级后，调用队列 API 可能触发断言？中断标志的清除顺序在哪查？

## M07：DMA 是否完全不需要 CPU？为什么要注意 Cache？ :id=m07

**参考回答：** CPU 负责配置通道、缓冲区和长度，并处理完成、错误与资源交接；DMA 硬件负责搬运。在有 D-Cache 且 DMA 不与 Cache 自动保持一致的平台，还要按照传输方向执行必要的 Cache clean/invalidate，并考虑缓存行对齐。

**易错点：** 不是所有 RAM 都能被所有 DMA 控制器访问，STM32H7 等平台要查看总线矩阵和 RAM 区域。`volatile` 不能修复 Cache 一致性。UART TX DMA 完成表示数据已交给外设，不一定表示移位寄存器最后一位已发送；RS-485 方向切换通常还要等发送完成标志。

**面试追问：** CPU 填好发送缓冲区后 DMA 却读到旧数据，先查什么？接收缓冲区与其他变量共用缓存行为什么危险？

## M08：PWM 频率和占空比怎么算？ :id=m08

**参考回答：** 对常见向上计数、边沿对齐定时器，`f_pwm = f_tim / ((PSC + 1) * (ARR + 1))`。在典型 PWM 模式下，占空比与 `CCR / (ARR + 1)` 相关，极性、模式与边界值要结合手册判断。修改频率会影响占空比分辨率。

**易错点：** `f_tim` 不一定等于 CPU 主频或 APB 总线频率；一些 STM32 时钟配置存在定时器倍频。中心对齐模式周期不同，不能直接照搬公式。舵机角度与脉宽的映射需要实测或规格依据，并非所有舵机都是同一范围。

**面试追问：** 若 `f_tim=72MHz`、`PSC=71`、`ARR=19999`，为什么输出 50Hz？`CCR=1500` 对应多长高电平？

## M09：ADC 位数越高，测量就越准吗？ :id=m09

**参考回答：** ADC 位数影响理想量化分辨率，实际精度还受参考电压、噪声、输入阻抗、采样时间、偏置与增益误差影响。理想单极性 N 位 ADC 的码值通常从 0 到 `2^N-1`，量化步长约为 `Vref / 2^N`，实际换算按器件传输特性处理。

**易错点：** 标称 12 位不等于有效 12 位精度。高阻信号源加过短采样时间可能导致采样电容充电不足。平均滤波可降低部分随机噪声，但不能自动消除参考偏差、错误接线或系统性误差。

**面试追问：** 同一输入换采样时间后读数变化，可能是什么原因？如何用已知电压、万用表和校准建立判断？

## M10：MCU 上电后为什么能进入 `main`？ :id=m10

**参考回答：** 以典型 Cortex-M 为例，复位启动涉及从选定启动映射读取初始栈指针与复位向量，再执行启动代码，完成必要的时钟/运行时初始化、`.data` 搬运、`.bss` 清零，最后进入 `main`。具体顺序由启动文件、库和平台决定。

**易错点：** 不同 ESP32 型号的内核与启动流程不同，常涉及 ROM、二级 Bootloader、分区与映像加载；不能把 Cortex-M 向量表流程套给所有芯片。有 Bootloader 的 MCU，应用起始地址、向量表与链接地址要一致。

**面试追问：** 为什么程序下载成功但到不了 `main`？如果 `.data` 没搬运或 `.bss` 没清零会发生什么？

## 动手验证

- [ ] 挑一个已经使用过的 I2C 传感器，记录手册地址、SDK 传参和抓到的地址字节，解释 ACK/NACK。
- [ ] 计算 M08 的 PWM 参数，再用示波器测量周期与脉宽；记录实际定时器时钟来源。
- [ ] 给 UART 协议连续输入半帧、两帧、错误长度，验证解析器不会依赖一次中断对应一帧。
- [ ] 阅读当前工程启动文件和链接脚本，找到复位入口、`.data`、`.bss` 与 `main` 的关系。

没有测量仪器时可以先分析手册与代码，但不要把“预计波形”写成“已经测得的波形”。
