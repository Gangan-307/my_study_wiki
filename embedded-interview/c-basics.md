# C 语言与内存易错题

[返回专区](index.md) | [复习与自测表](review-plan.md)

学习要求：能看懂短代码中的对象类型、存储期和访问边界，能解释编译器告警。以下以 C11/C17 和常见 MCU、Linux 工具链为背景，涉及大小与布局时必须说明目标 ABI。

## C01：数组和指针有什么区别？数组传参后还能求长度吗？

**参考回答：** 数组是一段连续的同类型元素，指针是保存地址的对象。数组表达式在多数场景会转换为首元素指针，但作为 `sizeof` 或一元 `&` 的操作数时不发生这种转换。函数形参里的 `int a[10]` 会调整为 `int *a`，因此不能在函数中靠 `sizeof(a)` 得到原数组长度，应另传元素个数。

**易错点：** 常见 32 位 MCU 的对象指针是 4 字节，AArch64 LP64 环境通常是 8 字节，但 C 标准不规定所有指针固定大小；函数指针与对象指针也不保证等大。`a` 和 `&a` 地址起点可能一样，类型与加一后的跨度不同。

**面试追问：** `int a[4]` 中 `a + 1` 和 `&a + 1` 分别跳过多少字节？为什么后者只能作为尾后指针，不能解引用？

**项目对应：** UART 接收函数同时传入 `buffer` 和 `length`，不要在接收函数里猜测缓冲区容量。

## C02：`sizeof` 和 `strlen` 有什么区别？字符串为什么容易越界？

**参考回答：** `sizeof` 是运算符，求类型或对象的字节大小；`strlen` 是库函数，读取字符直到 `\0`，返回终止符之前的长度。对 `char s[] = "abc"`，两者分别是 4 和 3。给 `strlen` 的内存必须包含可访问的终止符，UART 二进制数据不能直接当字符串。

**易错点：** `sizeof` 通常不计算操作数的值，但涉及变长数组时有例外。`strncpy` 在源长度达到上限时不保证补 `\0`；`snprintf` 应检查返回值是否小于 0 或大于等于容量。内存区域可能重叠时用 `memmove`，`memcpy` 不支持重叠。

**面试追问：** 容量为 8 的数组最多容纳多少个普通单字节字符组成的 C 字符串？为什么一次收满 8 字节后再写 `buf[8] = '\0'` 会出错？

## C03：`const int *p`、`int *const p` 有什么区别？

**参考回答：** `const int *p` 限制通过 `p` 修改目标，指针本身可以改；`int *const p` 限制指针改指向，但目标可以改；`const int *const p` 同时限制两者。`const` 表达访问约束，不保证对象一定放在 Flash 或只读段。

**易错点：** 若对象本来就是 `const`，强转去掉限定后修改它属于未定义行为。若原对象不是 `const`，经合法的可写别名仍可以修改。字符串字面量不可修改，建议用 `const char *p = "abc"`；`char s[] = "abc"` 则创建可修改的数组副本。

**面试追问：** `const volatile` 能同时使用吗？只读状态寄存器为什么可能使用它们？

## C04：`static` 和 `extern` 分别改变什么？

**参考回答：** 函数内 `static` 变量有静态存储期，跨函数调用保存值，名字的作用域仍在块内。文件作用域的 `static` 变量和函数具有内部链接，只在该翻译单元内可见。`extern` 常用于声明在其他位置定义的对象或函数，声明与定义需要区分。

**易错点：** C 中块作用域静态对象并不是每次进函数都初始化；没有显式初始化时按静态对象规则置零。`extern int x = 1;` 是定义。把变量定义放到公共头文件可能导致重复定义；头文件保护只能防止同一翻译单元重复包含。

**面试追问：** 驱动状态用文件内 `static` 隐藏后，多个任务调用这个驱动是否就线程安全？为什么还需要同步？

## C05：`volatile` 能解决并发问题吗？

**参考回答：** `volatile` 要求编译器按实现约定保留对对象的可观察访问，常用于内存映射寄存器等可能被程序正常执行路径以外因素改变的对象。它不保证读改写原子性，不提供互斥，也不建立 C 线程模型中的同步关系。共享资源应按平台选择原子操作、临界区或 RTOS 同步原语。

**易错点：** `volatile counter++` 仍可能涉及读、加、写多个步骤；它不是内存屏障，也不解决 DMA Cache 一致性。ISR 与主循环共享标志还要考虑访问宽度、访问顺序和事件是否丢失；多核共享更不能只加 `volatile`。

**面试追问：** 两个执行上下文都读到计数值 5，再分别写回 6，为什么少计一次？单条机器指令也一定能完成跨核同步吗？

**验证方式：** 先画交错执行顺序，再查看目标汇编；不要用存在 C 数据竞争的桌面线程实验结果来证明一种写法“可靠”。

## C06：栈、堆、全局变量的生命周期有什么区别？

**参考回答：** 普通局部对象通常有自动存储期，在离开作用域后失效，常由栈实现；动态分配对象在成功分配后有效，直到释放；全局和静态对象有静态存储期。典型 MCU 链接布局中，`.text` 放代码，`.rodata` 放只读数据，`.data` 的初值从 Flash 搬到 RAM，`.bss` 在启动时清零。

**易错点：** C 标准描述存储期，不保证某个局部对象一定占用物理栈空间。不能返回局部数组地址；静态数组虽可返回，但多次调用共享同一份数据。Linux 用户程序的地址通常是虚拟地址，不能直接当作 DMA 地址。

**面试追问：** 同样是 `char buf[128]`，加上 `static` 后生命周期、重入性和 RAM 占用如何变化？

## C07：`malloc/free` 最常见的错误有哪些？

**参考回答：** 检查分配失败、大小计算溢出、访问越界、重复释放、释放后使用和泄漏。分配数组前确认 `n <= SIZE_MAX / sizeof *p`，按对象类型计算大小。每块内存要明确谁拥有、谁释放、异步处理何时结束。

**易错点：** `free(NULL)` 合法；`free(p)` 后执行 `p = NULL` 只清除了这一个指针，其他别名仍可能悬空。不要直接把 `realloc` 返回值覆盖唯一旧指针，失败时旧块仍需管理。`malloc` 成功不代表内容已初始化。

**面试追问：** 把缓冲区指针放进队列后立刻 `free`，消费者为什么可能偶发崩溃？内存池如何减少分配抖动？

## C08：有符号数与无符号数混算为什么容易错？

**参考回答：** 小整数可能先做整数提升，再按通常算术转换统一类型。比较负数与无符号数时，负数可能被转换为很大的无符号数。例如 `-1 < 1u` 为假。无符号运算按类型范围取模；有符号溢出在 C11/C17 中属于未定义行为。

**易错点：** 在 `int` 为 32 位的平台，`uint8_t` 相减通常先提升为 `int`，结果不一定立即在 8 位回绕；存回 `uint8_t` 时又会转换。`size_t` 是无符号类型，反向循环写成 `i >= 0` 无法正常结束。

**面试追问：** 用无符号 Tick 差值判断超时，跨回绕是否可用？前提包括类型宽度一致、间隔范围合理，以及不能跨越无法区分的完整周期。

## C09：如何置位、清位？寄存器读改写有什么风险？

**参考回答：** 对普通无符号变量，第 `n` 位置位可以用 `v |= mask`，清位用 `v &= ~mask`，翻转用 `v ^= mask`。构造 32 位掩码可用 `UINT32_C(1) << n`，要求 `n < 32`。逻辑运算 `&&` 与按位运算 `&` 含义不同。

**易错点：** 移位数超出被提升后左操作数的位宽属于未定义行为；不要依赖有符号数左移溢出。寄存器可能有写 1 清零、读清除或保留位，不能机械套用 `|=`；某些 MCU 提供专门的置位/清位寄存器，应遵循手册。

**面试追问：** 两个上下文同时对同一寄存器读改写，即使修改不同位，为什么仍可能互相覆盖？

## C10：结构体为什么有填充？能直接发到串口吗？

**参考回答：** ABI 会要求成员和结构体整体按特定边界对齐，编译器可能在成员间和末尾插入填充。字段顺序、成员类型与对齐规则共同决定 `sizeof`。通信协议应明确字段宽度、字节序与编码，按字节序列化。

**易错点：** `packed` 是工具链相关扩展，可能造成未对齐访问、降低性能或触发异常，也不能解决字节序问题。直接发送结构体会把布局和潜在的未初始化填充字节一起发出。不要把任意字节缓冲区强转为结构体指针直接访问。

**面试追问：** 16 位数值 `0x1234` 用小端编码发送哪两个字节？字节序与 UART 在一个字节内部的位发送顺序是一回事吗？

## C11：宏和 `inline` 函数有什么区别？

**参考回答：** 宏在预处理阶段做文本替换，没有普通函数参数那样的类型检查，还可能多次求值。函数有明确参数类型；`inline` 不保证编译器一定展开。头文件内的小型 C 辅助函数常用 `static inline`，避免混淆 C 的外部链接规则。

**易错点：** `#define SQUARE(x) ((x) * (x))` 虽然补全括号，传入 `i++` 仍有问题；不能把这种代码当作确定输出题。多语句宏常用 `do { ... } while (0)` 包装，但仍应检查副作用。

**面试追问：** 为什么普通函数 `square(i++)` 只对实参求值一次？加了 `inline` 是否改变语言语义？

## C12：函数指针和回调有什么用？

**参考回答：** 函数指针指向兼容类型的函数，回调把具体处理逻辑传给框架。例如 `typedef void (*handler_t)(const uint8_t *, size_t, void *);` 可用于协议接收通知，`void *` 参数携带调用者上下文。

**易错点：** 不能随意强转不兼容的函数指针再调用。注册回调时要明确在哪个任务或中断上下文执行、是否允许阻塞、传入缓冲区有效到什么时候。回调中传来的指针不一定允许长期保存。

**面试追问：** 设备对象释放前如何注销回调，并确认已经在执行的回调结束？仅把回调指针设为 `NULL` 是否足够？

## 动手验证

下面是可在 WSL 或泰山派编译的完整实验，保存为 `c_basics_lab.c`。它用于观察 ABI、字符串、转换和位操作，没有执行越界或修改字面量等未定义行为。

```c
#include <inttypes.h>
#include <stddef.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>

struct Sample {
    char tag;
    uint32_t value;
    char state;
};

int main(void)
{
    int values[4] = {0};
    int *p = values;
    char text[] = "abc";
    int negative = -1;
    unsigned int positive = 1u;
    uint32_t mask = UINT32_C(1) << 3;
    uint32_t flags = 0;

    printf("array=%zu, pointer=%zu, count=%zu\n",
           sizeof values, sizeof p, sizeof values / sizeof values[0]);
    printf("sizeof(text)=%zu, strlen(text)=%zu\n",
           sizeof text, strlen(text));
    printf("struct=%zu, value_offset=%zu\n",
           sizeof(struct Sample), offsetof(struct Sample, value));
    printf("converted -1 < 1u: %d\n", (unsigned int)negative < positive);
    flags |= mask;
    printf("set=%" PRIu32 "\n", flags);
    flags &= ~mask;
    printf("clear=%" PRIu32 "\n", flags);
    return 0;
}
```

```bash
gcc -std=c11 -Wall -Wextra -Wconversion -O0 -g c_basics_lab.c -o c_basics_lab
./c_basics_lab
```

- [ ] 编译前预测输出，说明哪些结果取决于目标平台，哪些由 C 规则确定。
- [ ] 调整结构体字段顺序，比较 `sizeof` 与 `offsetof`，解释尾部填充。
- [ ] 去掉比较表达式中的显式转换，观察编译器对有符号/无符号比较的告警。
- [ ] 在自己的接收函数中补全缓冲区容量、有效长度、所有权约定。
