# 两周复习与自测表

[返回专区](index.md)

这份表覆盖首批 60 题，用于在当前项目和实习基础上准备面试。建议每天 40-60 分钟；遇到大小周、加班或一道题需要补实验，可把两周延长到三周。复习与投递同时进行，完成题库不是投递前置条件。

## 每次复习的安排

1. 5-10 分钟：闭卷复答上次最薄弱的 1-2 题。
2. 15-20 分钟：回答当日新题，读答案，标出自己遗漏的适用条件。
3. 15-25 分钟：完成一个小实验，或在项目中追踪对应调用链。
4. 5 分钟：本地记录一个仍答不清的问题与下一次动作。

如果实验超时，减少新题数量。已能解释并验证的题快速通过，把时间留给指针、同步、外设与真实排错中的薄弱点。

## 自测评分

| 分数 | 能力证据 | 下一步 |
| :--- | :--- | :--- |
| 0 | 无法解释概念 | 回到知识专题，看一个最小示例 |
| 1 | 能复述答案，变更条件就卡住 | 增加追问，写预测并做实验 |
| 2 | 能做实验并解释错误边界 | 在自己的项目里找到对应实现 |
| 3 | 能讲项目选择、故障修复与验证 | 准备代码修改题，检查回答是否过度概括 |

自测时至少回答三个问题：为什么这样设计？什么情况下会失败？怎样验证修复有效？不要把复述流畅程度作为唯一标准。

## 模拟面试怎么做

- **基础题：** 随机从 C、外设、RTOS 各选两题，要求补充平台、上下文与失败边界。
- **代码题：** 给接收函数增加容量检查，解释指针生命周期，或修复错误的任务同步；不只让代码编译通过。
- **项目题：** 沿数据流连续追问三层，例如“收到通知后谁处理、缓冲区何时释放、队列满了怎么办”。
- **故障题：** 给出“网线灯亮却 SSH 不通”或“打印日志后正常”的现象，要求先列验证步骤，不直接猜根因。
- **复盘：** 记录答不清的三处，下一次只补其中最影响主项目的一处。

## 两周验收

- [ ] 能解释并修改指针、字符串、位操作等短代码，不靠记住固定输出。
- [ ] 能说明 UART/I2C/SPI 的关键参数，并给出至少一种实际验证手段。
- [ ] 能为自己的任务通信选择合适原语，解释 ISR 限制和数据生命周期。
- [ ] 能区分网络关联、IP 配置、服务监听与身份认证，不把所有失败都归为密码问题。
- [ ] 能用自己的 ELF、日志或仪器结果讲清一次完整故障复盘。
- [ ] 能区分主项目中独立实现、集成 SDK、AI 辅助与尚未完成的部分。
- [ ] 已开始投递，并根据真实面试追问调整下一轮复习顺序。

基础练习不需要另起一个大型项目。优先复用现有手表、STM32、ESP32 Demo 和泰山派实验，让题目与已有代码形成对应。
