# 一、编程题

## 编程题 1：为 Person 类添加构造函数

### 参考代码

```cpp
Person(string n, int a) : name(n), age(a) {}
```

完整类如下：

```cpp
class Person {
public:
    string name;    // 姓名
    int age;        // 年龄

    Person(string n, int a) : name(n), age(a) {}

    void showPerson() {
        cout << name << " " << age << endl;
    }
};
```

### 解题思路

1. 题目要求"两个参数的构造函数"，即形参列表为 `(string, int)`。
2. 构造函数的**函数名必须与类名相同**，且**没有返回类型**（连 `void` 都不能写）。
3. 成员初始化优先使用**初始化列表** `: name(n), age(a)`，而不是在函数体里赋值。
4. `main` 中已经写好 `Person p(name, age);`，因此形参类型必须是 `string` 和 `int`，顺序不能颠倒。

### 为什么用初始化列表而不是函数体赋值

| 写法 | 过程 | 代价 |
|---|---|---|
| `Person(string n,int a){ name=n; age=a; }` | 先默认构造 `name`，再调用 `operator=` 赋值 | 多一次构造 + 一次赋值 |
| `Person(string n,int a): name(n), age(a) {}` | 直接用 `n` 拷贝构造 `name` | 只有一次构造 |

对 `int` 这种内置类型差别不大，但对 `string`、自定义类成员差别明显。此外，**const 成员和引用成员只能用初始化列表初始化**，因为它们不能被赋值。

### 易错点

- 写成 `void Person(...)` 或 `Person Person(...)` → 编译错误，构造函数不能有返回类型。
- 忘记 `public:`，或把构造函数写在 `private:` 下 → `main` 中无法构造对象。
- 参数写成 `(int, string)`，与 `main` 的调用顺序不符 → 类型不匹配。
- 使用 `name = n;` 却把成员声明为 `const string name;` → 编译错误。

### 延伸知识点

- **默认构造函数**：一旦用户自定义了任何构造函数，编译器就不再生成默认构造函数。若还需要 `Person p;`，必须自己补 `Person() = default;`。
- **`explicit`**：单参数构造函数建议加 `explicit`，防止 `Person p = "abc";` 这类隐式转换。
- **委托构造**（C++11）：`Person() : Person("", 0) {}`。

## 编程题 2：统计字符 a、b、c 的出现次数

### 参考代码（数组计数法）

```cpp
#include <iostream>
#include <string>

using namespace std;

int main() {
    string s;
    cin >> s;

    int cnt[3] = {0, 0, 0};

    for (char ch : s) {
        if (ch >= 'a' && ch <= 'c') {
            cnt[ch - 'a']++;
        }
    }

    cout << cnt[0] << " " << cnt[1] << " " << cnt[2] << endl;
    return 0;
}
```

### 解题思路

1. 字符集只有 `a`、`b`、`c` 三个，用长度 3 的计数数组即可，无需哈希表。
2. **字符到下标映射**：`ch - 'a'`。`'a'` 的 ASCII 是 97，`'b'` 是 98，`'c'` 是 99，相减得到 0、1、2。
3. 用**范围 for**（C++11）遍历字符串，比下标循环更简洁，也不会越界。
4. 输出格式：三个整数用空格隔开，末尾换行。

### 其他写法

**写法二：switch**

```cpp
int a = 0, b = 0, c = 0;
for (char ch : s) {
    switch (ch) {
        case 'a': ++a; break;
        case 'b': ++b; break;
        case 'c': ++c; break;
    }
}
cout << a << " " << b << " " << c << endl;
```

**写法三：`std::count`**

```cpp
#include <algorithm>
cout << count(s.begin(), s.end(), 'a') << " "
     << count(s.begin(), s.end(), 'b') << " "
     << count(s.begin(), s.end(), 'c') << endl;
```

复杂度 O(3n) = O(n)，常数略大但可读性好。

### 易错点

- 用 `cin >> s` 读取：遇到空白符停止。本题输入不含空格，没问题；若含空格需用 `getline`。
- 忘记初始化 `cnt` → 随机值。
- `cnt[ch - 'a']++` 前不判断范围，遇到其他字符会越界写内存（本题保证只有 a/b/c，但加上判断更安全）。
- 输出漏掉空格或漏掉换行。

### 延伸知识点

- **ASCII 连续性**：数字 `'0'`–`'9'`、大写 `'A'`–`'Z'`、小写 `'a'`–`'z'` 各自连续，这是 `ch - 'a'` 技巧的基础。
- **`cin >> s` 的返回值**：可用于判断输入是否成功，如 `while (cin >> s)` 处理多组输入。
- **范围 for 的陷阱**：`for (char ch : s)` 是值拷贝；要修改原串须写 `for (char& ch : s)`。

# 二、简答题

## 简答题 1：静态全局变量与函数内静态变量

### 参考答案

**一、文件作用域的静态全局变量**

1. **作用域**：文件作用域，但只在本编译单元（本文件）内可见，从定义点开始到文件结束。其他文件不能通过 `extern` 访问它。
2. **生存周期**：静态存储期，程序开始运行前创建，程序结束时销毁。

**二、函数内部的静态局部变量**

1. **作用域**：块作用域，只在函数内部可见，从定义点开始到函数结束。
2. **生存周期**：静态存储期，程序运行期间一直存在，不随函数调用结束而销毁。

### 深入解析

**关键结论：作用域和生存周期是两个正交的概念。**

| | 静态全局变量 | 函数内静态变量 | 普通局部变量 | 普通全局变量 |
|---|---|---|---|---|
| 作用域 | 文件（本编译单元） | 块（函数内） | 块 | 整个程序（可 extern） |
| 生存周期 | 静态存储期 | 静态存储期 | 自动存储期 | 静态存储期 |
| 存储位置 | 静态区（.data / .bss） | 静态区（.data / .bss） | 栈 | 静态区 |
| 初始化时机 | 程序启动前 | **首次执行到定义处时**（C++11 起线程安全） | 每次进入块 | 程序启动前 |
| 默认初值 | 0 | 0 | 不确定 | 0 |

**为什么静态全局变量外部访问不到？**

普通全局变量具有**外部链接**（external linkage），其他文件用 `extern` 声明即可引用。而 `static` 全局变量具有**内部链接**（internal linkage），链接器不会把它导出给其他编译单元，因此其他文件即使写 `extern int x;` 也链接不到（会报 undefined reference）。

**函数内静态变量为什么"只初始化一次"？**

编译器会为它分配静态存储区的空间，并生成一个隐藏的"是否已初始化"标志位（guard variable）。C++11 起，这个初始化过程由编译器保证**线程安全**（Magic Statics），因此可以安全地用于懒汉式单例。

```cpp
int& getInstance() {
    static int instance = 0;   // 首次调用时初始化，之后跳过
    return instance;
}
```

**典型用途**

- 函数内静态变量：计数器、缓存、单例对象。
- 静态全局变量：文件私有的辅助函数/数据，避免命名冲突（现代 C++ 更推荐匿名命名空间）。

### 延伸知识点：`static` 的三种含义

| 位置 | 含义 |
|---|---|
| 全局变量/函数前 | 内部链接，仅本编译单元可见 |
| 函数内局部变量前 | 静态存储期，只初始化一次 |
| 类成员前 | 属于类而非对象，所有对象共享，需在类外定义 |

## 简答题 2：成员函数如何区分不同对象的成员数据

### 参考答案

成员函数通过**隐式传入的 `this` 指针**来区分不同对象的成员数据。

因为对象的数据各自独立，而函数代码是共享的；调用时会把当前对象的地址绑定进来，函数内部通过 `this` 定位到具体对象的数据。

### 深入解析

**1. 编译器的实际转换**

```cpp
class Person {
public:
    string name;
    int age;
    void show() { cout << name << " " << age; }
};
```

编译器实际把它变成：

```cpp
void Person_show(Person* const this) {
    cout << this->name << " " << this->age;
}
```

调用 `p.show()` 被翻译为 `Person_show(&p)`。所以：

- **代码只有一份**，存放在代码段；
- **数据每个对象一份**，各自在内存中；
- `this` 就是"这份代码现在该操作哪块数据"的桥梁。

**2. `this` 指针的关键性质**

- `this` 是**非静态成员函数的隐含形参**，类型为 `Person* const`（指针本身不可改，指向的内容可改）。
- 在 `const` 成员函数中，`this` 的类型是 `const Person* const`。
- `this` 不是对象的一部分，`sizeof(对象)` 不包含它。
- 静态成员函数**没有 `this`**，因此不能直接访问非静态成员。

**3. 内存布局视角**

```
栈/堆:  p 对象 [ name | age ]        q 对象 [ name | age ]
                    ↑                            ↑
              this = &p                    this = &q
代码段:        show() 只有一份 ─────────────┘
```

**4. 为什么 `this` 能"区分"？**

因为成员访问 `name` 被编译为 `this->name`，即"基址 + 固定偏移量"。同一个 `show()` 函数里偏移量是常量，但基址 `this` 每次调用不同，于是自然访问到不同对象的数据。

### 延伸知识点

- `*this` 返回对象本身，链式调用 `return *this;` 常见于 `operator=`。
- 静态成员函数没有 `this`，所以不能是 `virtual`，也不能是 `const`。
- `delete this;` 是合法但危险的写法（要求对象由 `new` 分配且之后不再使用）。

## 简答题 3：分析程序运行结果

### 参考答案

**程序会崩溃，不会正常打印。**

1. `getMem1(str);` 是**按值传递**，形参 `p` 只是 `str` 的一份拷贝。
2. `p = new char[100];` 只让局部指针 `p` 指向新内存，并没有改变 `main` 中的 `str`。
3. 函数返回后 `p` 消失，新分配的 100 字节内存**泄漏**。
4. 此时 `str` 仍是 `NULL`。
5. 所以 `strcpy(str, "hello world !")` 向空指针写入，触发**段错误（Segmentation Fault）**，执行不到 `printf`。

### 深入解析

**1. 值传递的本质**

```cpp
void getMem1(char* p) { p = new char[100]; }
```

这里的 `p` 是 `char*` 类型的**值**。函数内修改 `p` 只修改这个副本，`str` 完全不受影响。

```
main:  str ──→ NULL
getMem1: p  ──→ NULL   （拷贝）
         p  ──→ [100 字节新内存]   （只改副本）
返回后: str 仍是 NULL，新内存无人指向 → 泄漏
```

**2. 三种正确的改法**

**改法一：传指针的指针**

```cpp
void getMem1(char** p) {
    *p = new char[100];
}
// 调用：getMem1(&str);
```

**改法二：传指针的引用（C++ 推荐）**

```cpp
void getMem1(char*& p) {
    p = new char[100];
}
// 调用：getMem1(str);   // 语法与原来一致
```

**改法三：返回指针**

```cpp
char* getMem1() {
    return new char[100];
}
// 调用：char* str = getMem1();
```

**3. 完整正确版本**

```cpp
#include <cstring>
#include <cstdio>

void getMem1(char*& p) {
    p = new char[100];
}

int main() {
    char* str = nullptr;
    getMem1(str);
    strcpy(str, "hello world !");
    printf("%s \n", str);
    delete[] str;          // 别忘了释放
    str = nullptr;         // 防止悬垂指针
    return 0;
}
```

### 易错点

- 误答"输出 hello world !"——这是最常见的错误，忽略了值传递。
- 只答"崩溃"而不解释原因，得分不完整。
- 忽略**内存泄漏**这一点（题目通常要求指出）。

### 延伸知识点

- **内存泄漏**：`new` 出来的内存没有对应 `delete`，程序运行期间无法回收。
- **悬垂指针**：`delete` 后指针仍指向已释放内存，再访问是未定义行为。
- **野指针**：未初始化的指针，指向随机地址。
- 现代 C++ 建议用 `std::string`、`std::vector`、`std::unique_ptr` 替代裸指针手工管理。

## 简答题 4：短跑名次推理

### 参考答案

**获得最后一名（第 9 名）的是王家的孩子。**

### 解题过程

**第一步：确定每家总分**

名次 1–9 对应分数 9, 8, 7, 6, 5, 4, 3, 2, 1。

总分 = 9 + 8 + … + 1 = 45。

三家总分相同 → 每家 = 45 ÷ 3 = **15 分**。

**第二步：列出各家的分数组合**

已知：
- 李家有第 1 名（9 分）；
- 王家有第 2 名（8 分）；
- 每家三个孩子分数和为 15；
- 同一家不能有相连名次（即分数不能是连续整数）。

**李家**：9 + 两数和 6。剩余可选分数中两数和为 6 的组合：
- {5, 1}
- {4, 2}
- {3, 3} —— 不允许（分数不能重复，名次唯一）

**王家**：8 + 两数和 7。组合：
- {6, 1}
- {5, 2}
- {4, 3} —— 相连，不允许

**第三步：逐一检验**

**假设李家取 {5, 1}**（即 9、5、1 分）：
剩余分数 {2, 3, 4, 6, 7}。
王家需要两数和为 7，只能从剩余中选：
- {6, 1} → 1 已被李家占用 ✗
- {5, 2} → 5 已被李家占用 ✗
- {4, 3} → 相连 ✗

无解，**假设不成立**。

**假设李家取 {4, 2}**（即 9、4、2 分）：
剩余分数 {1, 3, 5, 6, 7}。
王家需要两数和为 7：
- {6, 1} ✓（6 与 8 不相连，1 与 6 不相连）
- {5, 2} → 2 已被占用 ✗

所以王家 = {8, 6, 1}。

张家自动取得剩余 {7, 5, 3}，和 = 15 ✓。

**第四步：验证所有约束**

| 家庭 | 名次 | 分数 | 名次是否相连 | 总分 |
|---|---|---|---|---|
| 李家 | 1、6、8 | 9、4、2 | 1-6-8，不相连 ✓ | 15 |
| 王家 | 2、4、9 | 8、6、1 | 2-4-9，不相连 ✓ | 15 |
| 张家 | 3、5、7 | 7、5、3 | 3-5-7，不相连 ✓ | 15 |

全部满足。

**结论：第 9 名（最后一名，1 分）是王家的孩子。**

### 这类题的通用思路

1. **先算总量**：总分、总人数等不变量往往一步锁定关键数字。
2. **转化为组合问题**：把"名次"翻译成"分数"，把约束翻译成"集合划分"。
3. **枚举 + 剪枝**：对自由度最小的一家枚举，用约束快速排除。
4. **必须回代验证**：解出后逐条检查所有约束，避免漏掉隐含条件。

### 延伸知识点

- 本题本质是**约束满足问题（CSP）**，可用回溯搜索建模。
- 编程实现思路：对 1–9 的排列做全排列枚举（9! = 362880，完全可接受），按三条约束过滤。

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int main() {
    vector<int> p = {1,2,3,4,5,6,7,8,9};   // p[i] = 第 i+1 名属于哪家(0李,1王,2张)
    // 简化：直接枚举每家拿到的名次集合
    // 这里演示思路，实际可用三层循环 + 约束过滤
    return 0;
}
```

# 三、单项选择题

## 单选 2：关于构造函数的说法，错误的是

**答案：D**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 一个类中可以有多个构造函数 | ✅ 正确 | 构造函数可以**重载**，只要参数列表不同 |
| B. 构造函数没有返回类型 | ✅ 正确 | 连 `void` 都不能写，写了就是普通函数 |
| C. 只要对象被创建，就会执行构造函数 | ✅ 正确 | 对象构造必然调用某个构造函数（可能是编译器生成的） |
| D. 构造函数不可能是私有的 | ❌ **错误** | 构造函数**可以**是 private，这是单例模式的基础 |

### 为什么 D 错：私有构造函数的用途

**用途一：单例模式（Singleton）**

```cpp
class Singleton {
private:
    Singleton() {}                        // 私有构造，外部无法 new
    Singleton(const Singleton&) = delete;
public:
    static Singleton& getInstance() {
        static Singleton inst;            // 唯一实例
        return inst;
    }
};
```

**用途二：工具类 / 静态类**

```cpp
class MathUtil {
private:
    MathUtil() = delete;                  // 禁止实例化
public:
    static int abs(int x) { return x < 0 ? -x : x; }
};
```

**用途三：工厂模式**——构造函数私有，只能通过静态工厂方法创建对象。

### 易错点

- 误选 C：C 的表述"无论何时"稍显绝对，但对象创建确实必然经过构造函数（包括默认构造），故 C 正确。
- 混淆"构造函数可以是私有"与"构造函数必须是公有"。

### 延伸知识点

- 私有析构函数：用于限制对象只能分配在栈上（或配合 `shared_ptr` 自定义删除器）。
- `= delete` 比私有化更现代、报错更清晰。

## 单选 3：下列说法正确的有

**答案：D**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 静态方法中可以访问本类中的属性 | ❌ | 静态方法**没有 `this`**，不能访问非静态成员；只能访问静态成员 |
| B. 类方法中只能调用本类中的类方法 | ❌ | 可以调用其他类的静态方法、全局函数，也可以通过对象调用实例方法 |
| C. 类方法中绝对不能调用实例方法 | ❌ | 只要有对象（或指针/引用），静态方法中完全可以调用实例方法 |
| D. 一般方法中可用 this 调用本类属性 | ✅ | 非静态成员函数有 `this`，`this->name` 合法 |

### 深入解析

**A 为什么错**

```cpp
class A {
    int x;                 // 非静态成员
    static int y;          // 静态成员
public:
    static void f() {
        // x = 1;          // ✗ 错误：没有 this，不知道改哪个对象的 x
        y = 1;             // ✓ 可以访问静态成员
    }
};
```

**C 为什么错**

```cpp
class A {
public:
    void inst() {}
    static void stat(A& a) {
        a.inst();          // ✓ 有对象就能调用
    }
};
```

**D 为什么对**

```cpp
class A {
    int x;
public:
    void f() {
        this->x = 1;       // ✓
        x = 1;             // ✓ 等价，编译器自动加 this->
    }
};
```

### 延伸知识点

- 静态成员函数**不能**是 `virtual`、`const`、`volatile`。
- 静态成员变量必须在类外定义（C++17 起可用 `inline static` 就地定义）。
- `this` 的类型：普通成员函数中为 `A* const`，`const` 成员函数中为 `const A* const`。

## 单选 4：64 位系统中 sizeof(struct B)

**答案：A（32）**

### 逐步计算

**先看 `struct A`**

```cpp
struct A {
    int a;              // 4 字节，对齐 4
    union {
        long b;         // 8 字节，对齐 8
        short c;        // 2 字节
    };                  // 匿名 union
};
```

union 的大小 = 最大成员大小并向上对齐到最大对齐 = `max(8, 2)` = 8，对齐 8。

结构体 A 的布局（64 位 Linux，`long` 为 8 字节）：

| 成员 | 偏移 | 大小 |
|---|---|---|
| `a` | 0 | 4 |
| 填充 | 4 | 4 |
| union | 8 | 8 |
| **合计** | | **16** |

A 的最大对齐 = 8（来自 union 里的 `long`），16 已是 8 的倍数，所以 `sizeof(A) = 16`，`alignof(A) = 8`。

**再看 `struct B`**

```cpp
struct B {
    char e;             // 1 字节，对齐 1
    struct A d;         // 16 字节，对齐 8
    int f;              // 4 字节，对齐 4
};
```

| 成员 | 偏移 | 大小 | 说明 |
|---|---|---|---|
| `e` | 0 | 1 | |
| 填充 | 1 | 7 | 使 `d` 对齐到 8 |
| `d` | 8 | 16 | 占 8–23 |
| `f` | 24 | 4 | 占 24–27 |
| 尾部填充 | 28 | 4 | 使总大小对齐到 8 |
| **合计** | | **32** | |

B 的最大对齐 = 8（来自 `d`），总大小必须是 8 的倍数 → 28 向上取整到 **32**。

### 关键规则总结

1. **每个成员的偏移量必须是该成员对齐数的整数倍**（必要时插入填充字节）。
2. **结构体总大小必须是其最大对齐数的整数倍**（尾部填充）。
3. **union 的大小** = 最大成员大小，并对齐到最大成员的对齐数。
4. **64 位 Linux/macOS**：`long` = 8 字节；**64 位 Windows（LLP64）**：`long` = 4 字节。

> ⚠️ 注意平台差异：若在 64 位 Windows 上，`long` 只有 4 字节，则 union 大小 = 4，A = 8，B = 1+7+8+4+... = 24，答案会变成 D。本题答案取 A（32），说明按 LP64（Linux/macOS）模型计算。

### 易错点

- 忘记 `char e` 后面的 7 字节填充。
- 忘记最后的尾部填充（算出 28 就直接选）。
- 误以为 `short c` 决定 union 大小。
- 忽略 64 位下 `long` 的字节数差异。

### 延伸知识点

- `#pragma pack(n)` 可改变对齐方式（常用于网络协议/文件格式）。
- `alignof` / `alignas`（C++11）可查询和指定对齐。
- 调整成员顺序（大对齐放前面）可减少填充，节省内存。

## 单选 5：内存分配方式有哪些

**答案：B（以上都是）**

### 三种分配方式

| 方式 | 位置 | 生存期 | 典型写法 |
|---|---|---|---|
| 栈上创建 | 栈区 | 随作用域自动释放 | `int a;` / `int arr[10];` |
| 堆上分配（动态） | 堆区 | 手动 `new`/`delete` | `int* p = new int;` |
| 静态存储区分配 | 全局/静态区 | 程序运行期间 | `static int x;` / 全局变量 |

所以 A、C、D 都对，选 B。

### 深入解析：C++ 程序的内存分区

```
高地址
┌─────────────┐
│   栈区 stack │  ↓ 向下增长：局部变量、函数参数、返回地址
├─────────────┤
│             │
├─────────────┤
│   堆区 heap  │  ↑ 向上增长：new / malloc
├─────────────┤
│  .bss        │  未初始化/初始化为 0 的全局、静态变量
├─────────────┤
│  .data       │  已初始化的全局、静态变量
├─────────────┤
│  .rodata     │  常量区：字符串字面量、const 全局
├─────────────┤
│  代码段 .text │  可执行指令
└─────────────┘
低地址
```

### 延伸知识点

- 栈的大小通常 1–8 MB，递归过深会**栈溢出**。
- 堆由 `malloc`/`new` 管理，可能产生**内存碎片**。
- `new` 与 `malloc` 的区别：`new` 会调用构造函数、类型安全、失败抛 `bad_alloc`；`malloc` 只分配原始内存、返回 `void*`、失败返回 `NULL`。
- 现代 C++ 推荐 RAII：`std::vector`、`std::string`、智能指针。

## 单选 6：析构函数的特征

**答案：D**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 析构函数名与类名相同 | ❌ | 析构函数名是 `~类名`，多了波浪号 |
| B. 析构函数可以有一个或多个参数 | ❌ | 析构函数**不能有参数**，因此也不能重载 |
| C. 析构函数的定义只能在类体内 | ❌ | 可以在类内声明、类外定义 `A::~A() {}` |
| D. 一个类中只能定义一个析构函数 | ✅ | 无参数 → 无法重载 → 只能有一个 |

### 析构函数的完整特征

```cpp
class A {
public:
    ~A();                       // 类内声明
};

A::~A() { }                     // 类外定义，合法
```

- 名字为 `~类名`；
- **无参数、无返回类型**；
- **不能重载**，一个类只能有一个；
- 可以是 `virtual`（基类析构应声明为 virtual）；
- 可以是 `= default` 或 `= delete`；
- 可以是 private（限制对象只能在栈上创建，或配合智能指针）。

### 延伸知识点：虚析构函数

```cpp
class Base {
public:
    virtual ~Base() {}          // 必须 virtual
};
class Derived : public Base {
public:
    ~Derived() { /* 释放资源 */ }
};

Base* p = new Derived();
delete p;                       // 若 ~Base 非 virtual → 只调 ~Base，泄漏！
```

**规则：只要类可能被继承并通过基类指针删除，析构函数就应该是 virtual。**

## 单选 7：rearrange 函数执行后的链表

**答案：`2 1 4 3 6 5 7`**

### 手工模拟

初始链表：`1 → 2 → 3 → 4 → 5 → 6 → 7`

初始状态：`p = 1`，`q = 2`

**第 1 轮**（p=1, q=2）

```cpp
temp = p->value;        // temp = 1
p->value = q->value;    // 节点1 = 2
q->value = temp;        // 节点2 = 1
p = q->next;            // p = 节点3
q = p ? p->next : 0;    // q = 节点4
```

链表变为：`2 → 1 → 3 → 4 → 5 → 6 → 7`

**第 2 轮**（p=3, q=4）

交换后：`2 → 1 → 4 → 3 → 5 → 6 → 7`
`p = 节点5`，`q = 节点6`

**第 3 轮**（p=5, q=6）

交换后：`2 → 1 → 4 → 3 → 6 → 5 → 7`
`p = q->next = 节点7`，`q = p->next = NULL`（0）

**循环结束**（`while(q)` 为假）

最终结果：**`2 1 4 3 6 5 7`**

### 算法本质

这个函数做的是**相邻两两交换（pairwise swap）**，但只交换 `value`，不改变节点链接。

- `p` 指向每对的第一个节点；
- `q` 指向每对的第二个节点；
- 交换后 `p = q->next`（跳到下一对的第一个），`q = p ? p->next : 0`（下一对的第二个）；
- 若节点数为奇数，最后一个节点保持原位。

### 关键代码点解析

```cpp
if ((!list) || !list->next)
    return;
```

**边界处理**：空链表或只有一个节点，无需操作，直接返回。这是链表题的标准防御式写法。

```cpp
q = p ? p->next : 0;
```

**空指针保护**：三元运算符确保 `p` 为 `NULL` 时不会解引用。等价于：

```cpp
if (p) q = p->next; else q = 0;
```

### 易错点

- 误以为交换的是节点指针（那样会改变链表结构，但结果序列相同）。
- 奇数个节点时误以为最后一个也要参与交换。
- 手算时搞混 `p` 和 `q` 的推进顺序（`p = q->next` 用的是**交换后**的 `q`，但 `q->next` 没变，所以等价于原来的 `q->next`）。

### 延伸知识点

- 若要求**交换节点本身**（而非值），需要维护 `prev` 指针，代码复杂度显著上升。
- 只交换值的好处：实现简单；坏处：当节点是大型对象时拷贝代价高。
- 递归写法：

```cpp
ListNode* swapPairs(ListNode* head) {
    if (!head || !head->next) return head;
    ListNode* second = head->next;
    head->next = swapPairs(second->next);
    second->next = head;
    return second;
}
```

## 单选 8：两个同名函数的现象

**答案：C（重载）**

### 概念辨析

| 概念 | 英文 | 发生位置 | 条件 |
|---|---|---|---|
| **重载** | overload | **同一个类/作用域内** | 函数名相同，**参数列表不同** |
| **覆盖** | override | 派生类 vs 基类 | 函数名、参数、返回类型都相同，基类函数是 `virtual` |
| **隐藏** | hide/name hiding | 派生类 vs 基类 | 同名但参数不同，或基类非虚 |
| 继承 | inheritance | 类之间 | is-a 关系 |
| 封装 | encapsulation | 类设计 | 数据与操作绑定，隐藏实现 |

### 题目关键："在类的定义中"

题目强调"在 C++ **类的定义中**可以有两个同名函数"，即同一个类内部，因此是**重载**。

```cpp
class A {
public:
    void f(int x);          // 重载
    void f(double x);       // 重载
    void f(int x, int y);   // 重载
};
```

### 重载的判定规则

**只有参数列表（类型、个数、顺序）不同才算重载。**

以下**不能**构成重载：

```cpp
int  f(int x);
void f(int x);          // ✗ 仅返回类型不同，不是重载 → 编译错误
```

```cpp
void f(int x);
void f(int x = 0);      // ✗ 默认参数不同，不是重载 → 二义性
```

`const` 成员函数可以与非 const 版本构成重载：

```cpp
class A {
    void f();           // 非 const 版本
    void f() const;     // const 版本，构成重载
};
```

### 延伸知识点：名字修饰（name mangling）

C++ 编译器把重载函数编码成不同符号名，例如 GCC 下：

```
void f(int)     →  _Z1fi
void f(double)  →  _Z1fd
```

这正是 C++ 支持重载、而 C 不支持的底层原因，也是 `extern "C"` 存在的原因（见多选 2）。

## 多选 1：引用与指针的区别

**答案：B、C**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 引用初始化后能被改变，指针不可以改变所指对象 | ❌ **完全说反了** | 引用一旦绑定**不能改绑**；指针可以改指向 |
| B. 不存在指向空值的引用，但存在空值指针 | ✅ | 引用必须绑定到有效对象；指针可以是 `nullptr` |
| C. 引用必须被初始化，指针不必 | ✅ | `int& r;` 编译错误；`int* p;` 合法（但是野指针） |

### 引用与指针的完整对比

| 维度 | 引用 | 指针 |
|---|---|---|
| 是否必须初始化 | **必须** | 不必（但应初始化） |
| 能否为空 | 不能 | 能（`nullptr`） |
| 能否改绑/改指向 | **不能改绑** | 可以改指向 |
| 是否占内存 | 通常不单独占（编译器实现为常量指针，可能优化掉） | 占一个指针大小 |
| 是否可多级 | 无"引用的引用"（`int&&` 是右值引用） | 可多级 `int**` |
| 算术运算 | 不支持 | 支持 `p++`、`p+1` |
| `sizeof` | 得到被引用对象的大小 | 得到指针本身大小（8 字节 on 64 位） |
| 是否可为 `NULL` | 不可以 | 可以 |
| 底层实现 | 通常是指针的语法糖 | 直接存地址 |

### 代码验证

```cpp
int a = 1, b = 2;
int& r = a;
r = b;              // 这是赋值！a 变成 2，r 仍然绑定 a
// int& r2;         // ✗ 编译错误：引用必须初始化
// int& r3 = nullptr; // ✗ 编译错误：不能绑定空值

int* p;             // ✓ 合法（但危险）
p = &a; p = &b;     // ✓ 可以改指向
p = nullptr;        // ✓ 合法
```

### 延伸知识点

- **引用的本质**：编译器通常用指针实现，但语义上是"别名"，不占独立存储（标准未规定）。
- **常量引用**：`const int& r = 42;` 可以绑定临时量，会延长其生命周期。
- **右值引用**（C++11）：`int&& rr = 42;`，是移动语义的基础。
- 函数参数选择：小对象传值，大对象传 `const&`，需要修改传 `&` 或 `&`（非 const 引用）。

## 多选 2：`extern "C"{}` 的作用

**答案：A、D**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 主要解决在 C++ 代码中调用 C 代码 | ✅ | 这是最典型的用途 |
| B. 上述描述都不正确 | ❌ | A、D 正确，故 B 错 |
| C. 主要解决在 C 代码中调用 C++ 代码 | ❌ | 方向反了。`extern "C"` 是 C++ 的语法，C 编译器不认识 |
| D. 表明按类 C 的编译和连接规约来编译和连接 | ✅ | 准确描述了机制 |

### 核心原理：名字修饰（Name Mangling）

**C 编译器**：函数 `void foo(int)` 的符号名就是 `foo`。

**C++ 编译器**：为了支持重载，会把参数类型编码进符号名，GCC 下：

```
void foo(int)     →  _Z3fooi
void foo(double)  →  _Z3food
```

**问题场景**：C 语言写了一个库 `libc_math.a`，导出符号 `add`。C++ 代码声明 `int add(int,int);` 并调用，编译器生成的调用目标是 `_Z3addii`——链接器找不到这个符号，报 **undefined reference**。

**解决方案**：

```cpp
// C++ 侧
extern "C" {
    int add(int a, int b);     // 按 C 规则生成符号 "add"
}
```

### 标准头文件写法

```cpp
#ifdef __cplusplus
extern "C" {
#endif

int add(int a, int b);
void greet(const char* name);

#ifdef __cplusplus
}
#endif
```

这样同一个头文件既能被 C 编译，也能被 C++ 编译。

### 为什么 C 不能调用 C++

`extern "C"` 是 C++ 的关键字，C 编译器会直接报语法错误。C 调用 C++ 的正确做法是：**在 C++ 侧用 `extern "C"` 导出 C 风格的接口**，然后 C 侧正常声明即可。

```cpp
// cpp_impl.cpp
extern "C" int cpp_add(int a, int b) { return a + b; }
```

```c
/* main.c */
int cpp_add(int a, int b);      /* 普通 C 声明即可 */
```

### 易错点

- 误选 C：搞反了方向。
- 以为 `extern "C"` 能改变 C++ 的语义（如禁止重载）——它只影响**链接规约**，不影响语言语义。
- 注意：`extern "C"` 修饰的函数**不能重载**（因为符号名相同会冲突）。

### 延伸知识点

- `extern "C++"` 是默认规约，显式写出可用于嵌套场景。
- C++ 中 `extern "C"` 可以修饰单个函数、一组函数（花括号）、或整个头文件包含。
- 相关：`__cplusplus` 宏、`#ifdef __cplusplus` 条件编译。

## 多选 3：编译器自动生成的缺省函数

**答案：A、B、C、D（全选）**

### 编译器默认生成的成员函数

传统 C++98 有 4 个：

| 函数 | 签名 | 生成条件 |
|---|---|---|
| 默认构造函数 | `A()` | 用户未声明任何构造函数 |
| 拷贝构造函数 | `A(const A&)` | 用户未声明拷贝构造 |
| 拷贝赋值运算符 | `A& operator=(const A&)` | 用户未声明赋值运算符 |
| 析构函数 | `~A()` | 用户未声明析构函数 |

C++11 起增加 2 个：

| 函数 | 签名 | 说明 |
|---|---|---|
| 移动构造函数 | `A(A&&)` | 用户未声明拷贝/移动/析构时生成 |
| 移动赋值运算符 | `A& operator=(A&&)` | 同上 |

### 重要：生成规则与"三/五/零法则"

**只要用户声明了其中任何一个，编译器可能不再生成其他的：**

```cpp
class A {
public:
    A(const A&) {}          // 用户声明了拷贝构造
    // 默认构造函数不再生成！
    // 移动构造/移动赋值也不再生成！
};
```

**三法则（Rule of Three）**：需要自定义析构、拷贝构造、拷贝赋值中的任何一个，通常三个都需要。

**五法则（Rule of Five）**：C++11 后再加上移动构造和移动赋值。

**零法则（Rule of Zero）**：优先使用能自动管理资源的成员（`std::string`、`std::vector`、智能指针），从而一个都不需要写。

### 默认生成的版本做什么

- **默认构造**：对类类型成员调用其默认构造；对内置类型成员**不初始化**（值不确定）。
- **拷贝构造**：逐成员**浅拷贝**。
- **拷贝赋值**：逐成员**浅赋值**。
- **析构**：逐成员调用析构。

**浅拷贝的陷阱**：

```cpp
class Buffer {
    char* data;
public:
    Buffer(int n) : data(new char[n]) {}
    ~Buffer() { delete[] data; }
    // 使用编译器生成的拷贝构造 → 两个对象指向同一块内存
    // → 双重释放（double free）崩溃
};
```

必须自己写深拷贝，或用 `= delete` 禁止拷贝。

### 延伸知识点

- `= default`：显式要求编译器生成默认版本。
- `= delete`：显式禁止某个函数。
- 声明了移动构造后，拷贝构造会被删除（除非显式 `= default`）。

## 多选 6：程序的三种基本控制结构

**答案：B、C、D**

### 三种基本结构（Böhm–Jacopini 定理）

| 结构 | 英文 | 对应语句 |
|---|---|---|
| **顺序结构** | sequence | 语句自上而下依次执行 |
| **选择结构** | selection | `if` / `switch` / 三目运算符 |
| **循环结构** | iteration | `for` / `while` / `do-while` |

**A. 跳转结构（`goto`、`break`、`continue`、`return`）不属于三种基本结构。**

### 为什么"跳转"不算基本结构

Böhm 和 Jacopini 在 1966 年证明：**任何单入口单出口的算法都可以只用顺序、选择、循环三种结构表达**。这三种结构足以构成结构化程序，`goto` 是冗余的（虽然某些场景下有用，如跳出多层循环）。

结构化程序设计（Structured Programming）的核心主张就是**避免使用 `goto`**。

### 代码示例

```cpp
// 顺序
int a = 1;
int b = 2;
int c = a + b;

// 选择
if (c > 2) { /* ... */ } else { /* ... */ }
switch (c) { case 3: break; default: break; }

// 循环
for (int i = 0; i < 10; ++i) { /* ... */ }
while (cond) { /* ... */ }
do { /* ... */ } while (cond);
```

### 延伸知识点

- **单入口单出口**：结构化程序的基本要求，`goto` 可能破坏它。
- **`break`/`continue`/`return`** 是受限跳转，通常仍被视为结构化的一部分。
- 现代观点：`goto` 可用于统一错误清理（Linux 内核风格），但要克制。

## 多选 7：关于野指针的描述

**答案：A、B、D**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 指针指向的内存被释放后应指向 NULL | ✅ | 防止悬垂指针的标准做法 |
| B. 野指针指向无效内存地址，会导致崩溃或未定义行为 | ✅ | 定义准确 |
| C. 在变量作用域结束前释放地址空间并让指针指向 NULL | ❌ | 表述有误，见下 |
| D. 指针声明时初始化，可以是具体地址，也可指向 NULL | ✅ | 良好的编程习惯 |

### C 为什么错

原句："在变量的作用域结束前释放掉变量的地址空间并且让指针指向 NULL。"

问题在于：
1. **局部变量的地址空间不能手动释放**——它由栈自动管理，`delete` 一个栈变量是未定义行为。
2. 这句话把"释放 + 置空"当作野指针的**描述**，但它实际是**避免野指针的措施**，且措辞混乱（"作用域结束前释放"时机不对）。
3. 正确的防御措施是：**堆内存 `delete` 后立即置 `nullptr`**；栈变量无需也无法手动释放。

### 三种"坏指针"的区分

| 名称 | 定义 | 成因 |
|---|---|---|
| **野指针**（wild pointer） | 未初始化的指针，指向随机地址 | `int* p;` 后直接使用 |
| **悬垂指针**（dangling pointer） | 指向已释放/已失效内存的指针 | `delete p;` 后继续用 `p` |
| **空指针**（null pointer） | 值为 `nullptr` | 显式初始化，安全 |

> 严格来说，悬垂指针是野指针的一种；题目 B 用"指向无效内存地址"统称，是合理的宽泛定义。

### 防御措施

```cpp
// 1. 声明即初始化
int* p = nullptr;

// 2. 释放后置空
delete p;
p = nullptr;

// 3. 使用前检查
if (p != nullptr) { *p = 1; }

// 4. 优先用智能指针
std::unique_ptr<int> up = std::make_unique<int>(0);
```

### 延伸知识点

- `delete nullptr;` 是**安全**的（标准保证无操作），所以置空后重复 delete 不会崩。
- `delete` 同一块内存两次是未定义行为（double free）。
- 智能指针通过 RAII 从根本上消除悬垂指针问题。

## 多选 8：下列循环语句中有语法错误的是

**答案：B**

### 逐项分析

**A. `int i,j;for(i=1,j = 0;i<10;i++,j++) cout<<'*';`** ✅ 合法

- 初始化部分用逗号表达式 `i=1, j=0`，合法；
- 迭代部分 `i++, j++` 也是逗号表达式，合法。

**B. `for(1) cout<<'*';`** ❌ **语法错误**

`for` 的语法是：

```
for ( init-statement; condition; expression ) statement
```

三个部分之间的**分号是必需的**。`for(1)` 缺少两个分号，编译器报错：

```
error: expected ';' before ')' token
```

若想写无限循环，正确写法是：

```cpp
for(;;)      cout << '*';   // ✓
while(1)     cout << '*';   // ✓
for(;1;)     cout << '*';   // ✓
```

**C. `int i=0;for(;i<10;i++) cout<<'*';`** ✅ 合法

初始化部分为空（分号保留），合法。

**D. `int i;for(i=1;i<10;i++) cout<<'*';`** ✅ 合法

标准写法。

### `for` 语句的完整语法

```cpp
for ( init-statement ; condition ; expression )
    statement
```

- 三个部分都**可以为空**，但**两个分号不能省略**。
- `init-statement` 可以声明变量（C++ 允许，C99 也允许）。
- `condition` 为空等价于 `true`。
- C++11 范围 for：`for (decl : range)`，这是另一种形式，没有分号。

### 易错点

- 误选 A：逗号表达式在 `for` 中完全合法。
- 误以为 `for(1)` 等价于 `for(;1;)`——这是常见误解，两者语法不同。
- 注意题目问的是**语法错误**，不是"逻辑错误"或"死循环"。

### 延伸知识点

- `for(;;)` 与 `while(true)` 在优化后通常等价。
- 范围 for 的底层：`auto&& __range = range; auto __begin = begin(__range); ...`
- C++17 起支持 `for (auto [k, v] : map)` 结构化绑定。

## 多选 10：对象内存与指针的分配位置

**答案：A（堆区，栈区）**

### 题目解读

题目问："创建对象时，对象的内存和指向对象的指针分别分配在（ ）"

典型的语境是：

```cpp
Person* p = new Person();   // 对象在堆，指针 p 在栈
```

- **对象内存**（`new` 出来的 `Person`）→ **堆区**
- **指针变量 `p` 本身** → **栈区**（它是 `main` 的局部变量）

### 为什么不是其他选项

| 选项 | 分析 |
|---|---|
| B. 常量区，堆区 | 常量区存放字符串字面量、const 全局量，对象不在那里；指针也不在堆 |

| D. 栈区，堆区 | 顺序反了：栈上是指针，堆上是对象 |

### 需要补充的说明

严格来说，"对象的内存"取决于**创建方式**：

```cpp
Person p1;                  // 栈上（局部对象）
Person* p2 = new Person();  // 堆上
static Person p3;           // 静态区
```

本题选项的设定明显指向 `new` 的场景（否则"指向对象的指针"就无从谈起），因此选 A。

### 延伸知识点

- **栈对象**：自动析构，RAII 的基础，访问快。
- **堆对象**：手动管理生命周期，可跨函数存活，有分配开销。
- **`new` 的两步**：① 调用 `operator new` 分配内存；② 在内存上调用构造函数。
- **`delete` 的两步**：① 调用析构函数；② 调用 `operator delete` 释放内存。
- 对象大小：空类 `sizeof` 为 1（保证每个对象有唯一地址）。

## 多选 11：下面不是构造函数特征的是

**答案：B**

### 逐项分析

| 选项 | 是否为构造函数特征 | 说明 |
|---|---|---|
| A. 构造函数可以重载 | ✅ 是 | 参数列表不同即可重载 |
| B. 构造函数必须指定返回值类型 | ❌ **不是** | 构造函数**没有返回类型**，连 `void` 都不能写 |
| C. 构造函数可以设置默认参数 | ✅ 是 | `A(int x = 0)` |
| D. 构造函数的函数名与类名相同 | ✅ 是 | |

题目问"**不是**……特征的是"，选 B。

### 构造函数的完整特征清单

1. 函数名与类名相同；
2. **没有返回类型**（不能写 `void`，也不能 `return 值`）；
3. 可以被重载；
4. 可以有默认参数；
5. 不能是 `virtual`（构造时虚表尚未建立）；
6. 不能是 `static`；
7. 可以是 `explicit`（禁止隐式转换）；
8. 可以是 `private`/`protected`（限制实例化）；
9. 初始化列表在函数体之前执行；
10. 不能直接调用（除 placement new 和委托构造外）。

### 为什么构造函数不能是 virtual

虚函数调用依赖对象的 **vptr（虚表指针）**，而 vptr 是在**构造函数执行期间**才被初始化的。构造对象时对象还不存在，无法通过虚表找到"该构造哪个类型"，因此构造函数不能是虚函数。

### 易错点

- 误选 A：重载是完全正常的特性。
- 混淆"没有返回类型"与"返回 void"——前者是"不写"，后者是"写了 void"，两者不同。

### 延伸知识点

- **委托构造函数**（C++11）：`A() : A(0) {}`
- **继承构造函数**（C++11）：`using Base::Base;`
- **`explicit` 与隐式转换**：`A a = 1;` 在 `A(int)` 非 explicit 时合法。

## 多选 12：派生类对象可以访问基类成员中的

**答案：B（以上都错）**

### 逐项分析

题目问"**派生类对象**可以访问基类成员中的"，关键词是"**对象**"——即通过派生类对象从**外部**访问。

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 私有继承的公有成员 | ❌ | 私有继承后，基类 public 成员在派生类中变成 **private**，外部不可访问 |
| C. 公有继承的保护成员 | ❌ | protected 成员**只能被派生类内部**访问，外部对象访问不了 |
| D. 公有继承的私有成员 | ❌ | private 成员派生类**完全不可见** |
| B. 以上都错 | ✅ | |

### 访问权限矩阵（关键表）

**基类成员在派生类中的可见性：**

| 基类中的访问级别 | public 继承 | protected 继承 | private 继承 |
|---|---|---|---|
| public | public | protected | private |
| protected | protected | protected | private |
| private | 不可见 | 不可见 | 不可见 |

**谁能访问什么：**

| 访问者 | public | protected | private |
|---|---|---|---|
| 类自身成员函数 | ✅ | ✅ | ✅ |
| 派生类成员函数 | ✅ | ✅ | ❌ |
| 派生类**对象**（外部） | ✅（公有继承时） | ❌ | ❌ |
| 友元 | ✅ | ✅ | ✅ |

**关键结论**：
- **protected 成员**：派生类的**成员函数**可以访问，派生类的**对象**不可以。
- 私有继承的公有成员：在派生类中变成 private，**对象**访问不了。

### 代码验证

```cpp
class Base {
public:    int pub;
protected: int pro;
private:   int pri;
};

class PubDerived : public Base {
public:
    void f() {
        pub = 1;    // ✓
        pro = 2;    // ✓ 派生类成员函数可访问 protected
        // pri = 3; // ✗ private 完全不可见
    }
};

int main() {
    PubDerived d;
    d.pub = 1;      // ✓ 公有继承的公有成员，对象可访问
    // d.pro = 2;   // ✗ protected，对象不可访问
    // d.pri = 3;   // ✗ private

    class PriDerived : private Base { };
    PriDerived pd;
    // pd.pub = 1;  // ✗ 私有继承后变 private，对象不可访问
}
```

### 易错点

- 混淆"派生类成员函数可访问"与"派生类对象可访问"——这是本题的核心陷阱。
- 忘记私有继承会把 public 降级为 private。

### 延伸知识点

- `using Base::member;` 可以在派生类中提升访问权限（但不能提升 private）。
- `friend class Derived;` 可让派生类访问基类 private。
- 组合优于继承：能用组合就不要用继承。

## 多选 13：关于重载函数的正确说明

**答案：D**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 函数名相同，返回值类型不同 | ❌ | **仅返回类型不同不构成重载**，编译报错 |
| B. 函数名称不同 | ❌ | 名字不同就是不同函数，与重载无关 |
| C. 函数名相同，函数内部实现不同 | ❌ | 实现不同不是重载的**判定条件**（虽然实现通常不同） |
| D. 函数名相同，参数类型或个数不同 | ✅ | 重载的准确定义 |

### 重载的判定条件

**必须满足：同一作用域 + 函数名相同 + 参数列表不同。**

参数列表不同包括：
- 参数**类型**不同：`f(int)` vs `f(double)`
- 参数**个数**不同：`f(int)` vs `f(int, int)`
- 参数**顺序**不同：`f(int, double)` vs `f(double, int)`

**不能**构成重载的情况：

```cpp
int  f(int);        // 1
double f(int);      // ✗ 仅返回类型不同 → 重定义错误

void f(int);        // 1
void f(int = 0);    // ✗ 默认参数不同，调用 f(1) 时二义性

void f(int*);       // 1
void f(int[]);      // ✗ 数组参数退化为指针，与 1 相同
```

### const 成员函数的重载

```cpp
class A {
public:
    void f()       { cout << "non-const"; }
    void f() const { cout << "const"; }
};
```

这是合法的重载——`const` 对象调用 const 版本，非 const 对象调用非 const 版本。

### 重载决议（overload resolution）

编译器按以下顺序选择最佳匹配：

1. **精确匹配**（exact match）
2. **提升转换**（promotion）：`char`→`int`、`float`→`double`
3. **标准转换**（conversion）：`int`→`double`、`double`→`int`
4. **用户定义转换**（user-defined conversion）
5. **省略号匹配**（`...`）

若多个候选同样好 → **二义性错误**。

### 延伸知识点

- 重载 vs 覆盖 vs 隐藏（见单选 8）。
- `const` 重载是 `std::vector::operator[]` 的经典用法。
- 模板 + 重载：非模板版本优先于模板版本。

## 多选 14：以下符号不是 C++ 运算符的是

**答案：A（`@`）**

### 逐项分析

### C++ 运算符完整分类

### 关于 `@` 的说明

`@` 在某些语言中有特殊含义：
- C#：`@` 用于逐字字符串（`@"C:\path"`）和标识符转义（`@class`）
- Python：`@` 是装饰器语法
- Java：`@` 是注解（annotation）

但 **C++ 没有 `@` 运算符**。C++ 中 `@` 甚至不是合法的标识符字符，出现在代码中会直接报语法错误。

### 易错点

- 混淆 `|`（按位或）和 `||`（逻辑或）——两者都是运算符。
- 以为 `!` 只能用于 bool——`!` 可用于任何可转换为 bool 的表达式。

### 延伸知识点

- **运算符优先级**：`!` > 算术 > 关系 > `&&` > `||` > 赋值。
- **运算符重载**：除 `::`、`.`、`.*`、`?:`、`sizeof` 外，几乎都可重载。
- `and`、`or`、`not` 是 `&&`、`||`、`!` 的替代拼写（C++ 保留字）。

## 多选 15：赋值运算符与拷贝构造函数的区别与联系

**答案：B**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 拷贝构造能 copy，赋值运算符不可以 | ❌ | 赋值运算符同样能拷贝对象 |
| B. 都是将一个对象 copy 到另一个中去 | ✅ | 这是两者的**联系**（共同点） |
| C. 都不能将一个对象 copy 到另一个中去 | ❌ | 显然错误 |
| D. 赋值运算符能 copy，拷贝构造不可以 | ❌ | 同样错误 |

题目问的是"区别与**联系**"，B 准确描述了**联系**，故为正确项。

### 两者的本质区别（题目未考但必须掌握）

| 维度 | 拷贝构造函数 | 赋值运算符 |
|---|---|---|
| 签名 | `A(const A&)` | `A& operator=(const A&)` |
| 调用时机 | **创建新对象**时 | 对象**已存在**时 |
| 是否构造新对象 | 是 | 否 |
| 返回值 | 无 | `A&`（支持链式赋值） |
| 是否可自赋值 | 不涉及 | 必须处理 `a = a` |

**代码示例：**

```cpp
A a1;
A a2 = a1;      // 拷贝构造（初始化）
A a3(a1);       // 拷贝构造
a3 = a1;        // 赋值运算符（a3 已存在）

A a4 = a1;      // 注意！这是拷贝构造，不是赋值
```

**关键陷阱**：`A a4 = a1;` 看起来像赋值，实际是**初始化**，调用的是拷贝构造函数。

### 为什么区分很重要

```cpp
class Buffer {
    char* data;
public:
    Buffer(const Buffer& o) {           // 拷贝构造：分配新内存
        data = new char[strlen(o.data) + 1];
        strcpy(data, o.data);
    }
    Buffer& operator=(const Buffer& o) { // 赋值：先释放旧内存
        if (this != &o) {                // 自赋值检查
            delete[] data;
            data = new char[strlen(o.data) + 1];
            strcpy(data, o.data);
        }
        return *this;
    }
};
```

- 拷贝构造时 `data` 还是野值，**不能** `delete[]`；
- 赋值时 `data` 指向旧内存，**必须**先释放，否则泄漏。

### 延伸知识点

- **自赋值安全**：`a = a;` 必须先判断 `this != &o`。
- **返回值优化**：`A a = f();` 可能被编译器优化掉拷贝。
- **移动语义**：`A(A&&)` 和 `A& operator=(A&&)` 用于窃取资源。
- **copy-and-swap 惯用法**：`A& operator=(A o) { swap(o); return *this; }` 自动处理自赋值和异常安全。

## 多选 16：关于函数的描述正确的是

**答案：B**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 派生类虚函数与基类虚函数参数个数和类型不同 | ❌ | 那叫**隐藏**，不是覆盖；要实现多态必须**签名完全相同** |
| B. 基类说明虚函数后，派生类对应函数可不必说明 virtual | ✅ | 一旦是虚函数，派生类中同名同签名函数**自动是虚函数** |
| C. 虚函数是一个非成员函数 | ❌ | 虚函数**必须是类的非静态成员函数** |
| D. 虚函数是一个 static 型的函数 | ❌ | 静态成员函数**没有 `this`**，不能是虚函数 |

### 逐项深入

**A 为什么错：签名必须一致**

```cpp
class Base {
public:
    virtual void f(int x) { }
};

class Derived : public Base {
public:
    void f(double x) { }    // ✗ 参数不同 → 这是隐藏，不是覆盖
};

Base* p = new Derived();
p->f(1);                    // 调用 Base::f，不是 Derived::f
```

C++11 引入 `override` 关键字，让编译器帮你检查：

```cpp
class Derived : public Base {
public:
    void f(double x) override;   // ✗ 编译错误：没有可覆盖的虚函数
};
```

**B 为什么对**

```cpp
class Base {
public:
    virtual void f() { }
};

class Derived : public Base {
public:
    void f() { }        // ✓ 自动是虚函数，无需再写 virtual
};
```

`virtual` 属性是**继承**的，一旦在基类声明，派生类中同签名的函数自动成为虚函数。

**C 为什么错**

```cpp
virtual void f();       // ✗ 全局函数不能是 virtual
```

虚函数依赖对象的 vptr 和虚表，全局函数没有对象，无法实现动态绑定。

**D 为什么错**

```cpp
class A {
public:
    static virtual void f();   // ✗ 编译错误
};
```

静态成员函数属于类而非对象，没有 `this`，无法通过 vptr 查找，因此不能是虚函数。

### 虚函数规则总结

| 规则 | 说明 |
|---|---|
| 必须是成员函数 | 不能是全局函数 |
| 不能是 static | 没有 this |
| 不能是构造函数 | 构造时 vptr 未建立 |
| 可以是析构函数 | **基类析构应为 virtual** |
| 可以是 private | 仍可被覆盖（NVI 惯用法） |
| 签名必须一致 | 否则是隐藏 |
| `final` 可禁止覆盖 | C++11 |
| 纯虚函数 `= 0` | 使类成为抽象类 |

### 延伸知识点

- **虚表（vtable）**：每个多态类一张，存虚函数地址。
- **vptr**：每个对象一个，指向所属类的虚表，通常占 8 字节。
- **动态绑定**：通过基类指针/引用调用虚函数时，运行时查表决定调用哪个版本。
- **对象切片**：`Base b = derived;` 会丢失派生部分，多态失效。

## 多选 17：函数指针声明解读

**答案：B**

### 代码解读

```cpp
void (*f)(int *, int *);
```

**解读顺序**（"右左法则"）：

1. 从标识符 `f` 开始；
2. 先看右边：`)`，说明 `f` 被括号包住，往左看；
3. 左边是 `*`，说明 `f` 是一个**指针**；
4. 跳出括号，右边是 `(int*, int*)`，说明指向**函数**，参数是两个 `int*`；
5. 最左边是 `void`，说明该函数**返回 void**（无返回值）。

**结论：`f` 是一个函数指针，指向"参数为两个 `int*`、返回 `void`"的函数。**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 声明了一个返回值为指针的函数 f | ❌ | 那是 `void* f(int*, int*);` |
| B. 定义了函数的指针 f，f 所指函数无返回值 | ✅ | 准确 |
| C. 声明了一个无返回值的函数 f | ❌ | 那是 `void f(int*, int*);`（没有 `(*f)`） |
| D. 定义了函数的指针 f，f 所指函数返回指针 | ❌ | 返回类型是 `void`，不是 `void*` |

### 关键：括号的位置决定一切

```cpp
void (*f)(int*, int*);      // 函数指针：f 指向函数
void* f(int*, int*);        // 函数：返回 void* 指针
void  f(int*, int*);        // 函数：返回 void
void* (*f)(int*, int*);     // 函数指针：所指函数返回 void*
```

**记忆口诀**：`(*f)` 表示 f 是指针；`f(...)` 表示 f 是函数。括号优先级高于函数调用。

### 函数指针的实际用法

```cpp
#include <iostream>
using namespace std;

void add(int* a, int* b) { cout << *a + *b; }

int main() {
    void (*f)(int*, int*);   // 声明
    f = add;                 // 赋值（函数名退化为指针）
    int x = 1, y = 2;
    f(&x, &y);               // 通过指针调用，输出 3
    (*f)(&x, &y);            // 等价写法
}
```

### 更复杂的声明

```cpp
void (*arr[5])(int*);        // 函数指针数组：5 个函数指针
void (*(*p)(int))(double);   // 返回函数指针的函数指针
typedef void (*FuncPtr)(int*, int*);   // 用 typedef 简化
using FuncPtr2 = void(*)(int*, int*);  // C++11 using 别名
```

### 延伸知识点

- 函数指针是**回调**机制的基础（如 `qsort` 的比较函数）。
- 现代 C++ 更推荐 `std::function` 和 lambda。
- 函数指针可以比较、可以作为参数传递、可以存入容器。
- 成员函数指针：`void (A::*p)(int);`，调用需 `(obj.*p)(1)`。

## 多选 18：关于 delete 和 delete[] 的区别

**答案：A**

题目问"描述**错误**的是"。

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 对于内建简单数据类型，delete 和 delete[] 功能是不相同的 | ❌ **错误** | 对 POD 类型，两者**行为等价**（都不会调用析构函数，只释放内存） |
| B. new 配 delete，new[] 配 delete[] | ✅ 正确 | 标准配对规则 |
| C. 自定义复杂类型，两者不能互用；delete[] 删数组，delete 删指针 | ✅ 基本正确 | 会调用不同次数的析构函数 |
| D. delete 调用一次析构，delete[] 调用每个元素的析构 | ✅ 正确 | 表述中"每一个成员函数的析构函数"应为"每一个元素的析构函数"，属笔误 |

### A 为什么错：POD 类型的行为等价

```cpp
int* p1 = new int[10];
delete[] p1;        // 正确

int* p2 = new int[10];
delete p2;          // 对 int 而言：内存能正确释放（大多数实现下）
```

对 `int`、`char`、`double` 这类**没有析构函数**的类型，`delete` 和 `delete[]` 都只是"释放内存"，差别仅在于是否调用 `operator delete[]`。实践中多数实现能正确释放，**但标准上这是未定义行为**，绝不能依赖。

### 为什么对自定义类型必须区分

```cpp
class A {
public:
    A()  { cout << "ctor "; }
    ~A()  { cout << "dtor "; }
};

A* p = new A[3];    // 构造 3 次
delete p;           // ✗ 只析构 1 次（p[0]），p[1]、p[2] 的资源泄漏
delete[] p;         // ✓ 析构 3 次
```

`delete[]` 需要知道数组长度才能逐个析构。编译器在 `new[]` 时会在内存块头部**额外存储元素个数**（cookie），`delete[]` 读取它来决定循环次数。

### 为什么不能混用

```
new[] 分配的内存布局：
┌────────┬─────┬─────┬─────┐
│ cookie │ [0] │ [1] │ [2] │   ← cookie 存元素个数 3
└────────┴─────┴─────┴─────┘
         ↑
    new[] 返回的是这里（跳过 cookie）

delete  → 从 cookie 位置开始释放 → 地址错误 → 崩溃
delete[] → 正确回退到 cookie 位置 → 正确释放
```

对 POD 类型，编译器可能不写 cookie，所以"看起来能用"；对含析构函数的类型，cookie 一定存在，混用必然崩溃。

### 最佳实践

```cpp
// 1. 严格配对
int* p = new int;        delete p;
int* q = new int[10];    delete[] q;

// 2. 用容器代替裸数组
std::vector<int> v(10);  // 自动管理

// 3. 用智能指针
auto up = std::make_unique<int[]>(10);   // C++14
```

### 延伸知识点

- `new[]` 的 cookie 大小通常为 8 字节（64 位）。
- 用 `delete` 释放 `new[]` 是**未定义行为**，即使"没崩溃"也不代表正确。
- `malloc`/`free` 与 `new`/`delete` 也不能混用。

## 多选 19：函数参数默认值

**答案：B**

### 逐项分析

| 选项 | 判断 | 说明 |
|---|---|---|
| A. 多个参数时，默认值设定可以不连续 | ❌ | **必须从右向左连续**设定 |
| B. 设定默认值后，该参数后面所有参数都必须设定默认值 | ✅ | 这正是"从右向左"规则的等价表述 |
| C. 函数参数必须设定默认值 | ❌ | 完全可以不设 |
| D. 带默认值的参数只能有一个 | ❌ | 可以有多个 |

### 核心规则：默认参数必须从右往左连续

**合法：**

```cpp
void f(int a, int b = 2, int c = 3);   // ✓ 右侧连续
void f(int a, int b = 2);              // ✓
void f(int a = 1, int b = 2, int c = 3); // ✓ 全部有默认值
```

**非法：**

```cpp
void f(int a = 1, int b, int c = 3);   // ✗ 中间的 b 没有默认值
void f(int a = 1, int b);              // ✗ 左侧有、右侧没有
```

**为什么必须这样？**

因为函数调用时实参是**从左到右**依次匹配形参的。若允许"中间空缺"，编译器无法判断：

```cpp
void f(int a = 1, int b);   // 假设合法
f(5);                       // 5 是给 a 还是给 b？无法确定
```

### 默认参数的其它规则

**1. 默认值只能指定一次**

```cpp
void f(int a = 1);      // 声明时给默认值
void f(int a) { }       // ✗ 定义时不能再给（重定义默认参数）

// 正确写法：
void f(int a = 1);
void f(int a) { }       // ✓ 定义处不写默认值
```

**2. 默认值可以是表达式，但必须是编译期可确定的**

```cpp
int g();
void f(int a = g());    // ✓ 合法（调用时才求值）
void f(int a = 1 + 2);  // ✓
```

**3. 默认参数与虚函数**

```cpp
class Base {
public:
    virtual void f(int x = 1) { cout << "Base " << x; }
};
class Derived : public Base {
public:
    void f(int x = 2) override { cout << "Derived " << x; }
};

Base* p = new Derived();
p->f();     // 输出 "Derived 1"（函数体是 Derived 的，默认值是 Base 的！）
```

**陷阱**：默认参数是**静态绑定**（编译期确定），虚函数是**动态绑定**。两者混用极易出错。

### 延伸知识点

- 默认参数可以简化重载的数量，但过多默认参数会降低可读性。
- 构造函数常用默认参数：`A(int x = 0, int y = 0)`。
- 默认参数不能用于**函数指针类型**的声明中（某些场景）。

## 多选 20：错误的数组说明语句

**答案：A**

### 逐项分析

**A. `int d[3][] = {{1, 2}, {1, 2, 3}, {1, 2, 3, 4}};`** ❌ **错误**

二维数组定义时，**只有第一维可以省略**（由初始化列表推导），**其余维度必须给出**。

`int d[3][]` 中第二维为空，编译器无法确定每个元素的步长（一行多少列），故报错：

```
error: array type has incomplete element type
```

正确写法：

```cpp
int d[3][4] = {{1, 2}, {1, 2, 3}, {1, 2, 3, 4}};   // ✓ 第二维给 4
int d[][4]  = {{1, 2}, {1, 2, 3}, {1, 2, 3, 4}};   // ✓ 第一维省略
```

**B. `int a[2][3];`** ✅ 合法

标准二维数组声明，未初始化（元素值不确定）。

**C. `int c[100][100] = {0};`** ✅ 合法

`{0}` 把第一个元素初始化为 0，**其余元素自动初始化为 0**。这是 C/C++ 的聚合初始化规则。

**D. `int b[][3] = {0, 1, 2, 3};`** ✅ 合法

第一维省略，由初始化列表推导：4 个元素 ÷ 每行 3 个 → 需要 2 行。

```cpp
int b[][3] = {0, 1, 2, 3};
// 等价于
int b[2][3] = {{0, 1, 2}, {3, 0, 0}};
```

### 二维数组的维度规则

```cpp
int a[3][4];        // ✓ 3 行 4 列
int a[][4];         // ✓ 第一维可省（需同时初始化）
int a[3][];         // ✗ 第二维不可省
int a[][] = {...};  // ✗ 两维都省，无法推导
```

**原因**：C++ 的二维数组本质是"数组的数组"。`int a[3][4]` 是"3 个 `int[4]` 组成的数组"。编译器必须先知道 `int[4]` 的大小（16 字节）才能计算 `a[1]` 的地址（`a + 1 * 16`）。若第二维未知，`a[1]` 的地址就算不出来。

### 内存布局

```cpp
int a[2][3] = {{1,2,3},{4,5,6}};
// 内存中连续排列：
// a[0][0] a[0][1] a[0][2] a[1][0] a[1][1] a[1][2]
//    1        2        3        4        5        6
```

`a[i][j]` 的地址 = `a + (i * 3 + j) * sizeof(int)`

### 延伸知识点

- **`{0}` 初始化**：`int arr[100] = {0};` 把全部元素置 0，是常用技巧。
- **`std::array`**：`std::array<std::array<int,3>,2> a;` 更安全。
- **变长数组（VLA）**：`int a[n];` 是 C99 特性，**不是标准 C++**（GCC 作为扩展支持）。
- **动态二维数组**：`vector<vector<int>>` 或一维数组手动索引 `a[i*m+j]`。

## 高频易错点 TOP 10

1. **值传递不改实参**——简答 3 的核心，也是面试高频题。
2. **构造函数没有返回类型**——写 `void` 就错了。
3. **protected 成员：派生类成员函数可访问，派生类对象不可访问**——多选 12 的陷阱。
4. **仅返回类型不同不构成重载**——多选 13。
5. **默认参数必须从右向左连续**——多选 19。
6. **二维数组只有第一维可省略**——多选 20。
7. **`delete` 与 `delete[]` 对自定义类型不可混用**——多选 18。
8. **`extern "C"` 是 C++ 调用 C，不是反过来**——多选 2。
9. **`for(1)` 是语法错误，不是无限循环**——多选 8。
10. **64 位下 `long` 在 Windows 是 4 字节、Linux 是 8 字节**——单选 4 的平台差异。

## 建议的学习路径

1. **先补基础**：内存分区、指针与引用、作用域与生存周期。
2. **再攻类与对象**：构造/析构/拷贝控制三件套（三法则、五法则）。
3. **然后继承与多态**：访问权限矩阵、虚函数、虚表。
4. **最后抠细节**：重载决议、默认参数、对齐规则、`extern "C"`。
5. **动手验证**：每道题都写代码跑一遍，尤其是 `sizeof`、对齐、`delete` 相关题目，不同编译器结果可能不同。
