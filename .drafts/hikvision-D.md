### Q1｜TCP/IP 分层与 FTP 协议所在层
**题干：** 1. 请问 TCP/IP 协议分为哪几层？ FTP 协议属于哪一层？

**解析：** 原文按层职责逐条展开（压缩）：
- 应用层：应用程序间沟通的层，如 SMTP、**FTP**、Telnet 等；
- 传输层：提供节点间数据传送、应用间通信服务，主要功能是数据格式化、数据确认和丢失重传，如 TCP、UDP；
- 互连网络层：负责基本的数据封包传送，让每块数据包到达目的主机（但不检查是否正确接收），如 IP；ARP 是地址解析协议，在这一层把 IP 地址转换为物理地址；
- 网络接口层（主机-网络层）：接收 IP 数据报并传输、从网络上接收物理帧、抽取 IP 数据报转交下一层，定义如何使用实际网络（Ethernet、Serial Line 等）传送数据。

另附「OSI 七层所对应协议」清单（原文逐层）：应用层（应用程序网关、Telnet、FTP、HTTP、SMTP、POP3、SNMP、DNS）／传输层（传输网关、TCP、UDP）／网络层（多协议路由器、IP、ARP、RARP、ICMP、IGMP、BOOTP）／数据链路层（网桥、交换机、HDLC、SLIP、PPP、802.2）／物理层（中继器、集线器——放大或再生弱的信号，在两个电缆段之间复制每一个比特）。

### Q3｜static 的作用（全局静态变量 / 局部静态变量 / 静态函数）
**题干：** 3. 在 c 语言中， static 函数与普通函数有什么区别？

**选项：** 无（问答）

**答案：** 原文无「标准答案」小节，通篇即答案，按三点组织（压缩照录）：
1. **全局静态变量**：位置=静态存储区（整个程序运行期间都存在）；未初始化的自动置 0；作用域=声明它的文件之外不可见，准确讲从定义之处开始到文件结尾。好处：① 不会被其他文件访问、修改 ② 其他文件可用同名变量而不冲突。
2. **局部静态变量**：位置=静态存储区；未初始化自动置 0；作用域仍为局部作用域，定义它的函数/语句块结束时作用域随之结束。注：`static` 修饰局部变量时把它从栈改存到静态存储区，离开作用域不销毁、驻留内存直到程序结束，只是不能再访问；修饰全局变量时改变作用域但不改变存放位置。
3. **静态函数**：在返回类型前加 `static`。函数定义/声明默认是 `extern`，静态函数只在声明它的文件中可见、不能被其他文件使用。好处：① 其他文件可定义同名函数不冲突 ② 静态函数不能被其他文件所用。
补充：存储说明符 `auto`、`register`、`extern`、`static` 对应两种存储期（自动存储期／静态存储期）；`static` 声明的局部变量具有静态存储持续期，值在函数调用之间保持有效，但名字可视性仍限制在局部域内，且在程序执行到声明处时首次初始化。
历史说明（原文）：`static` 最初表示「退出块后仍存在」的局部变量；后来在 C 中表示「不能被其它文件访问」的全局变量和函数（为避免新增关键字而复用）；C++ 又赋予第三种含义「属于类而非属于某个对象」。

**解析：** 原文用一段对比代码给结论，输出为 `a=20;b=5` / `i=334` / `i=335`（代码含 `extern int a; static int b= 5;` 与 `func2()` 里的 `static int i= 333; i++;`）。作者结论原话：「总的来说，静态的东西就是只在本文件中可见，而且在本文件中保持，它只初始化一次，存在静态存储区中，再对它进行初始化不会引起错误，但是没有用了」。

### Q8｜`n & (n-1) == 0` 判断什么
**题干：** 8、解释n&(n-1) == 0是用来判断什么

**解析：** 原文无解析。【自核】`n&(n-1)` 会抹掉 `n` 最低位的 1；结果为 0 说明 `n` 二进制里只有一个 1，即 `n` 是 2 的幂。注意两个坑：① 运算符优先级——`==` 高于 `&`，实际要写成 `(n & (n-1)) == 0`；② `n = 0` 时 `0 & (-1) == 0` 也成立，所以严格判断 2 的幂须写成 `n != 0 && (n & (n-1)) == 0`。

**解析：** 原文无展开解析（只有作者一句「一眼见，D」）。【自核】`case`／`if-else`／`casez`（以及 `casex`）都是分支语句；`repeat` 是**循环**语句（`repeat(n) ...`，按表达式值决定循环次数，初值可为 0 则可能一次都不执行），故不是分支语句。

### Q2｜`reg[0:31]` 与 indexed part-select `hik[0:+8]` 的含义
**题干：** 2、（3分）对于 reg[0:31] ，表达式 hik[0:+8]指的是 ？

**选项：** 无（题干如此，原文未见选项文字）

**答案：** 原文无答案（免费部分未给出文字答案）

**解析：** 原文只写了「IEEE的 Verilog 标准对此的原文表述：」并贴了一张标准原文截图，再写「 示例：」并贴第二张示例截图——**两张图片中的文字未能取得，不做转写**。
<!-- 截断 -->（自此处起被付费墙「订阅专栏 解锁全文」挡住，第 3 题及之后（多选、问答：形式验证/网表验证/乘法器/多周期约束/SRAM/存储层次/AMBA/指令集架构等）均无法抓取。）

【自核】（独立于原文，供核对）：`reg [0:31] hik;` 是**升序声明**的向量，索引 0 是最高位（MSB）、索引 31 是最低位。`hik[0:+8]` 是 indexed part-select（`[base +: width]`）：从 `base = 0` 开始、沿**索引增大方向**连续取 `width = 8` 位，即等价于 `hik[0:7]`——对 `[0:31]` 这种升序向量恰好是最高 8 位（也就是常规 `[7:0]` 降序写法下的低 8 位这一类混淆点，需按方向判断而不是按「高位=大索引」想当然）。要点：`+:` 起点向索引增大方向、`-:` 起点向索引减小方向；`base` 可为变量，`width` 必须为常量，这正是 `hik[var-7 : var]` 这类可变起点选择必须改用 part-select 语法的原因。
