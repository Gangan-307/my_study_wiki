### 【P1-6】关于互斥锁的如下表述错误的是（）
- 选项：A. 互斥锁的加锁和解锁必须由同一线程分别对应使用　B. 互斥锁只能为 0/1　C. 互斥锁的解锁过程不需要关心顺序，只需要成对使用即可　D. 互斥锁用于线程的互斥
- **答案：C**
- 解析（原文）：互斥量和信号量的区别 —— **互斥量用于线程的互斥，信号量用于线程的同步**，这是根本区别；互斥量值只能为 0/1，信号量值可以为非负整数，所以一个互斥量只能用于一个资源的互斥访问，不能实现多个资源的多线程互斥问题；**互斥量的加锁和解锁必须由同一线程分别对应使用，信号量可以由一个线程释放，另一个线程得到**。原文另附"互斥 vs 同步"区分：互斥指某一资源同时只允许一个访问者访问，具有唯一性和排它性，但无法限制访问顺序；同步是在互斥基础上通过其它机制实现访问者对资源的有序访问。
- 来源：https://blog.csdn.net/qq_38410730/article/details/82686282 ✅ ／ 同题镜像：https://blog.csdn.net/weixin_30272849/article/details/112037721 ⚠️ ／ https://blog.csdn.net/weixin_39855186/article/details/110933154 ⚠️

### 【P1-21】可用于中断下半段处理的处理机制有（）【多选】
- 选项：A. tasklet　B. 工作队列　C. 软中断　D. 双向链表
- **答案：ABC**
- 解析（原文）：上半部是不能中断的，仅仅是响应中断；下半部是可以中断的。上半部功能是响应中断，把设备驱动中断处理例程的下半部挂到下半部执行队列后继续等待新中断，因此执行速度快；下半部负责处理比较复杂的流程，可被其它中断打断。三种机制对比（原文表格）：**软中断**（中断上下文、复杂度高、执行性能好、无顺序保证）、**tasklet**（中断上下文、复杂度中、性能中、同类型不能同时执行）、**工作队列**（进程上下文、复杂度低、性能差、和进程上下文一样被调度）。
- 来源：https://blog.csdn.net/qq_38410730/article/details/82686282 ✅

### 【P1-简答2】设计或开发 Linux 操作系统的内核时，你会考虑哪些基本的管理模块，并描述其作用。
- **答案（原文）**：Linux 内核的五大模块 —— **进程调度模块、内存管理模块、文件系统模块、进程间通信模块、网络接口模块**。
  - 进程调度模块：负责控制进程对 CPU 资源的使用，调度策略使各进程能公平合理访问 CPU，同时保证内核能及时执行硬件操作；
  - 内存管理模块：确保所有进程能安全共享机器主内存区，支持虚拟内存管理方式，使 Linux 支持进程使用比实际内存空间更多的内存容量，并可利用文件系统把暂时不用的内存数据块交换到外部存储；
  - 文件系统模块：支持对外部设备的驱动和存储，虚拟文件系统（VFS）向所有外部存储设备提供通用文件接口，隐藏各种硬件设备的不同细节；
  - 进程间通信模块：支持多种进程间的信息交换方式；
  - 网络接口模块：提供对多种网络通信标准的访问并支持许多网络硬件。
- 来源：https://blog.csdn.net/qq_38410730/article/details/82686282 ✅

### 【P15-2】死锁相关（题干为图片，未抓到文字）
- **解析（原文）**：死锁指在线程间共享多个资源时，两个线程分别占有一部分资源并且同时等待对方的资源。**产生死锁的四个必要条件**：① 互斥条件：一个资源每次只能被一个进程使用；② 请求与保持条件：一个进程因请求资源而阻塞时，对已获得的资源保持不放；③ 不剥夺条件：进程已获得的资源在未使用完之前不能被强行剥夺；④ 循环等待条件：若干进程之间形成一种头尾相接的循环等待资源关系。**预防死锁**：有序分配锁资源可以预防死锁；银行家算法**避免**死锁（不是检测），从当前状态出发逐个按安全序列检查各客户谁能完成工作。**解除死锁**：剥夺死锁进程的所有资源可以解除死锁。

### 【P15-4】文件系统存储结构（题干为图片，未抓到文字）
- **解析（原文）**：顺序结构（顺序存取+随机存取）优点：简单、支持顺序与随机存取、顺序存取速度快、所需磁盘寻道次数和寻道时间最少；缺点：需要为每个文件预留若干物理块以满足文件增长需要、不利于文件插入和删除。链式结构（仅顺序存取）优点：提高磁盘空间利用率、有利于插入删除、有利于文件动态扩充；缺点：存取速度慢不适于随机存取、连接指针出错时数据丢失、更多寻道次数和时间、链接指针占空间降低空间利用率。索引结构（顺序+随机存取）优点：不需预留物理块、既能顺序又能随机存取、满足文件动态增长与插入删除要求；缺点：较多寻道次数和时间、索引表本身带来系统开销。Hash 文件：用函数将关键字映射到存储器地址，按关键字计算目标地址再检索。

- 解析（原文）：① **const（只读）**——修饰变量告诉编译器该变量不允许被程序修改，典型场景是存放在 Flash 中的查表数据，如 `const uint16_t sine_table[256] = {...}`；修饰函数参数如 `void write_reg(const uint8_t *data)` 表示不修改 data 指向的内容。② **volatile（可被意外修改）**——告诉编译器该变量可能被"程序之外"的因素改变，禁止编译器优化掉读写操作；三种典型应用场景：硬件寄存器 `volatile uint32_t *reg = (volatile uint32_t *)0x40020000;`、中断中修改的全局变量、RTOS 中多任务共享的变量；原文给出经典错误示范：`uint8_t flag = 0; void ISR(void){ flag = 1; } void main(){ while(!flag); }`，编译器可能把 `while(!flag)` 优化成死循环。③ **static（作用域/生命周期控制）**——修饰局部变量把生命周期延长到整个程序运行期但作用域不变（`void f(){ static int cnt = 0; cnt++; }` 每次调用累加）；修饰全局变量/函数限定在当前文件内可见，防止命名冲突。原文还提到面试追问"const 和 volatile 能同时用吗"，答可以，例如只读硬件寄存器 `const volatile uint32_t status_reg`。

### 【P4-2】请问 TCP/IP 协议分为哪几层？FTP 协议在哪一层？

### 【P5-B卷-2】请比较面向连接服务和无连接服务的异同点，TCP/UDP 分别是什么服务，QQ 聊天通信中使用的是哪种服务？
- **答案（原文）**：面向连接（connection-oriented）在发送任何数据之前要求建立会话连接（与拨打电话类似），传送完成后需要释放连接；建立连接需要分配相应资源如缓冲区以保证通信正常进行，通常称为"可靠"的网络业务，可以保证数据以相同顺序到达，面向连接的服务在端系统之间建立通过网络的虚链路。无连接（connectionless）不要求发送方和接收方之间的会话连接，发送方只是简单地开始向目的地发送数据分组（数据报），与手机短信非常相似；此业务不如面向连接的方法可靠，但对于周期性的突发传输很有用，系统不必为它们保留状态信息。无连接网络提供最小的服务，仅仅是连接；优点是通信比较迅速、使用灵活方便、连接开销小，但可靠性低，不能防止报文的丢失、重复或失序，适合于传送少量零星的报文。**TCP 是面向连接，UDP 是无连接。QQ 是 UDP。**
- 来源：https://blog.csdn.net/zqxdsy/article/details/102574851 ⚠️

### 【P5-B卷-5】什么是域名解析及域名解析的过程？
- **答案（原文）**：英文缩写 DNS（Domain Name System），简单的说就是把你在浏览器地址栏输入的网页地址解析成 IP 地址；由于 IP 地址是用四段数字组成，相对英文来说不好记，通过域名解析就可以不用记 IP 地址。过程：① 客户机提出域名解析请求，并将该请求发送给本地的域名服务器；② 本地域名服务器收到请求后先查询本地缓存，如果有该记录项就直接把查询结果返回；③ 如果本地缓存中没有该记录，则本地域名服务器就直接把请求发给根域名服务器，然后根域名服务器再返回给本地域名服务器一个所查询域（根的子域）的主域名服务器的地址；④ 本地服务器再向上一步返回的域名服务器发送请求，然后接受请求的服务器查询自己的缓存，如果没有该记录则返回相关的下级的域名服务器的地址；⑤ 重复第四步直到找到正确的记录；⑥ 本地域名服务器把返回的结果保存到缓存以备下一次使用，同时还将结果返回给客户机。
- 来源：https://blog.csdn.net/zqxdsy/article/details/102574851 ⚠️

### 【P5-B卷（另一套）-2】完整介绍 TCP 的三次握手过程。（可用图解）
- **答案（原文）**：在 TCP/IP 协议中，TCP 协议提供可靠的连接服务，采用三次握手建立一个连接。**第一次握手**：建立连接时，客户端发送 syn 包（syn=j）到服务器，并进入 SYN_SEND 状态，等待服务器确认；**第二次握手**：服务器收到 syn 包，必须确认客户的 SYN（ack=j+1），同时自己也发送一个 SYN 包（syn=k），即 SYN+ACK 包，此时服务器进入 SYN_RECV 状态；**第三次握手**：客户端收到服务器的 SYN+ACK 包，向服务器发送确认包 ACK(ack=k+1)，此包发送完毕，客户端和服务器进入 ESTABLISHED 状态，完成三次握手。
- 来源：https://blog.csdn.net/zqxdsy/article/details/102574851 ⚠️

### P15-第一题：栈与堆的区别（题干为图片）
- **解析（原文要点）**：栈由操作系统（编译器）自动分配释放，用于存放函数的参数值、局部变量等；堆由开发人员分配和释放，容易产生内存碎片，若开发人员不释放，程序结束时由 OS 回收，分配方式类似链表。堆栈区别：① 管理方式不同（栈由 OS 自动分配释放，堆由程序员控制，容易内存泄漏）；② 空间大小不同（栈远小于堆，64 位 Windows 默认栈 1MB、64 位 Linux 默认 10MB）；③ 生长方向不同（堆向上、地址由低到高；栈向下、地址由高到低）；④ 分配方式不同（堆都是动态分配的，没有静态分配的堆；栈有静态和动态分配两种）；⑤ 分配效率不同（栈效率高、堆效率低，栈在硬件层级有专门的寄存器存放栈地址、压栈出栈有专门指令）；⑥ 存放内容不同（栈存放函数返回地址、相关参数、局部变量和寄存器内容等）。
- 来源：https://blog.csdn.net/weixin_44933419/article/details/114040147 ⚠️

## 备考建议（基于以上真题分布）

1. **主战场是 C 语言**：海康笔试卷中 C 语言占比最高，且以"给代码求输出"形式出现（宏展开、指针偏移、位操作、switch 穿透、memcpy 重叠）。先把本仓库 `c-language/` 下的 `pointer.md`、`operators.md`、`bitwise-registers.md`、`arrays.md`、`strings-buffers.md`、`memory-undefined-behavior.md` 过一遍。
2. **操作系统只要概念级熟练度**：进程 vs 线程、同步 vs 互斥、信号量 vs 互斥量、进程状态与调度触发条件、死锁四条件、中断上半部/下半部、内核态/用户态边界、Linux 内核五大模块、insmod/modprobe/rmmod。
3. **计算机网络背"分层 + 握手 + DNS 流程 + 协议归属"**，特别注意 **htons/htonl/ntohs/ntohl 与大小端**；子网划分在海康嵌入式笔试中未出现（但技术支持岗/其他公司可能考）。
4. **内存对齐要会算**：`sizeof(struct)`、`#pragma pack(n)` 的影响，这是 2013/2014 两套卷都考过的题型。
5. **安防业务相关要能说出标准名**：H.264/H.265、MPEG 系列、视频信号传输方式、RTSP/GB28181（面试层面）。
6. **卷面结构参考**：2019 BSP = 25 选择 + 2 简答；2022 应用开发 = 15 单选 + 7 多选 + 1 编程填空 + 2 编程；2023 提前批 = 15 单选 + 5 多选 + 2 简答 + 1 编程。**没有独立的大题量编程卷**，编程题难度为"链表实现队列""读取文件大小""递归求 2^N"量级。
